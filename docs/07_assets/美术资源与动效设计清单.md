# 美术资源与动效设计清单

日期：2026-10-11。阶段：浏览器版视觉资产生成与审核。本文盘点首个自研游戏十三张及其 H5 大厅、通用平台页面；其他游戏运行模块仍是 Stub。数量分别说明 AI 源图、程序派生图和动画成品，不将精灵图与切片重复计为 AI 生成量。

## 1. 统计边界与结论

- 场景、角色、头像和装饰由 AI API 生成；确定性 UI 和规则数据由 H5/Pixi 绘制。整副 52 张牌由代码绘制点数、花色、角标和点位，J/Q/K 中心人物使用 AI 角色插画。
- 静态图片的线上格式默认 WebP；PC 大厅八款游戏卡背景按专属 SDD 使用静态 AVIF poster，并保留同构图 WebP fallback。动效源以透明 WebP 精灵图提交审核，构建 AVIF 动画，并保留 WebP 帧图集作为 Pixi 的兼容与逐帧控制源。
- 子厅与难度档位由配置决定。厅名、金币上下限、人数、状态和主题色动态渲染；不为每个金币档位单独生成一张图。
- 多端尺寸通过安全区裁切、缩放和少量布局变体处理，不按每台设备重复生成美术。
- 支付渠道标识使用渠道/支付商提供的官方图标或文字，不能让模型仿制支付宝、微信、银联、银行或数字人民币商标。客服附件是用户上传资源，不计入 AI 美术。

玩家头像已经改为纯二维动画头像：男女各一张 5×5 精灵图，程序精确切成 **50 张待审 WebP**；早期偏写实头像已标记为被替代。扑克牌统一改成传统白底、红黑花色、双向角标和经典宫廷牌构图；牌点与花色由程序绘制，当前有 **52 张规则准确的牌面 WebP 待审**。11 张宫廷插画已按传统套色版画重做；黑桃 J 的请求状态为 `UNKNOWN`，为避免重复计费暂时复用梅花 J 插画，黑桃 J 的牌角和花色仍由代码正确绘制。旧牌面和旧宫廷人物候选已标记为被替代。牌局动效已有 **7 个 AI 关键帧图集**，每个裁为 16 帧并编码为透明 AVIF 动画，播放速率 12 fps、单次播放。所有新输出仍需人工审核；完整状态见 [`assets/aigen/十三张新增美术候选索引.json`](../../assets/aigen/十三张新增美术候选索引.json)。

## 3.1 静态图片分辨率档位与渐进加载

**可行，建议采用“一个审核通过的高质量母版，程序派生多档 WebP”**，不为每个档位分别调用 AI。母版保留在内部素材库，不进入客户端；由构建/素材流水线按目标尺寸缩放、编码、生成内容哈希并写入资源 manifest。运行时先显示低清版本，再根据显示尺寸、设备 DPR 和网络估算结果选择是否下载中档/高清版并替换纹理。这是多文件的渐进增强，不是单张图片内部的 progressive JPEG 解码。

| 档位 | 参考尺寸（长边） | 编码目标 | 用途 |
| --- | ---: | --- | --- |
| 低清 L | 128–256 px | WebP 有损，质量约 35–50 | 首屏占位、游戏目录卡、列表缩略图 |
| 中清 M | 384–768 px | WebP 有损，质量约 55–70 | 普通设备与常见卡片/弹窗显示 |
| 高清 H | 1024–1536 px，按实际显示上限 | WebP 有损或无损（需透明边缘时实测） | 大屏背景、高清屏放大显示 |

尺寸与质量只是初始编码档位，最终按视觉验收和文件体积调整，不对所有图像强制套用同一尺寸。比如入口图标通常只需 L+H 两档；封面适合 L/M/H；超宽大厅或牌桌背景需要匹配其横向构图，不能把方形小图简单放大成高清。52 张牌按统一规则生成 384×512 WebP；低清牌面和高清选中态由构建阶段派生，不重复调用 AI。AVIF 动画不做多档动态替换；按网络情况决定是否加载当前 C 位动画，加载失败时显示静态 WebP poster。PC 卡带静态 poster 的 AVIF 是独立例外，按专属 SDD 生成并同时提供 WebP fallback。

**运行顺序：**进入大厅时加载 L 并立即展示；网络调度器用已观测吞吐、延迟和失败/重试情况估算保守带宽，在用户操作优先级更高时暂停或降级后台任务；满足策略后在网络空闲窗口预取 M/H。高清版成功解码后，仅替换仍在屏幕上的对应纹理，保持裁切、宽高比、锚点不变，可用短淡入避免闪烁。下载/解码失败就保留现有版本；换场景或不再引用旧纹理后释放 GPU 纹理，缓存响应由 PWA 策略另行管理。不能因为已开始下载就同时常驻三份纹理。

变体选择应以实际渲染像素而不是整个屏幕分辨率为准：目标像素约为 CSS 显示尺寸 × DPR，并设置上限，避免 4K 屏导致后台资源无意义膨胀。网络指标只决定是否、何时继续升级，不应延迟首屏 L 的展示。母版变体使用独立 URL/别名和哈希版本，避免 Pixi 缓存将不同档位误当作同一资源；资源调度层显式管理 L→M→H 依赖和取消/降级。

PixiJS Assets 支持 WebP/AVIF、manifest/bundle 和资源解析；解析器可按分辨率选择资源，后台加载器可用于非阻塞加载，Sprite 也允许运行时替换纹理。分阶段下载仍需由应用按顺序调用加载，并由上述调度层决定时机：

- [PixiJS Assets](https://pixijs.com/8.x/guides/components/assets)
- [PixiJS Asset Manifest](https://pixijs.com/8.x/guides/components/assets/manifest)
- [PixiJS Resolver](https://pixijs.com/8.x/guides/components/assets/resolver)
- [PixiJS Background Loader](https://pixijs.com/8.x/guides/components/assets/background-loader)
- [PixiJS Sprite Texture](https://pixijs.com/8.x/guides/components/scene-objects/sprite)

## 5. 动效目录：服务器状态决定播放，AI 提供装饰帧

### Pixi/CSS 实时动作（首版，不按帧生成图片）

1. 发牌：牌背从牌堆按座位顺序飞入手牌区，时间轴由服务器阶段/本地节奏控制。
2. 拖拽与摆牌：选中抬升、吸附到三墩、重排、非法状态提示。
3. 自动摆牌/提示：牌组移动和目标墩高亮。
4. 提交与等待：提交确认、对手准备/超时状态、弱网重连状态。
5. 开牌比较：头/中/底三墩复用同一套翻牌、并排、胜负高亮序列。
6. 比分和金币变化：H5/Pixi 数值滚动，不能烘焙进特效素材。
7. 打枪：以金绿光扫关键帧表现三墩全胜奖励，不出现枪械/子弹；路径、命中和震屏由 Pixi 控制。
8. 全垒打：配置开启且服务端确认战胜其余玩家后，播放扇形庆祝光效。
9. 特殊牌型加水：配置开启且服务端判定该奖励后，播放牌框高亮；具体牌型名称由代码显示。
10. 结算：胜/负弹层播放各自的 AVIF 装饰层；金额、比分、按钮和文字由 H5 实时渲染。
11. 大厅卡片悬停/点击、非牌局弹窗和骨架屏：CSS transform/opacity，不需要 GIF/AVIF。

这些动画要由游戏状态驱动并能暂停、重放或在重连后跳过。把整段发牌/比牌烘焙成动图会使牌面和服务器实际结果无法对应。

大厅与牌局的动作音效映射、OpenAI 音频生成能力边界及 WebM/Opus、AAC 兼容策略，单独见[游戏音效设计与资源清单](./游戏音效设计与资源清单.md)。

每项以 4×4 关键帧精灵图生成，裁为 16 个 400×400 帧后编码为透明 AVIF，12 fps、单次播放。Pixi 使用源 WebP 精灵图逐帧更新纹理，H5 弹层可使用 AVIF；弱网下跳过 AVIF 时由 Pixi 使用同一 WebP 帧表播放。

OpenAI 旧 Videos/Sora API 已于 **2026-09-24** 下线，本批不依赖该接口；动效由图像模型生成关键帧，再在本地裁帧/编码。[OpenAI API deprecations](https://developers.openai.com/api/docs/deprecations)
