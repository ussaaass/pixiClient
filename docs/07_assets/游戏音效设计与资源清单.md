# 游戏音效设计与资源清单

阶段：首版音效盘点与制作方案。范围覆盖 Vue/H5 大厅、账户与客服交互、十三张 PixiJS 牌局及实时通知。首版仅规划短音效，不加入持续背景音乐或语音播报。

## 1. 设计原则

- 有明确动作反馈，但同类交互复用音色：按钮不各自生成一条；同一类事件使用同一音效，可轻微改变音高/声像，避免重复感。
- 不给每一张牌或每一帧动画单独配音。发 13 张牌使用一个带轻微变化的牌声序列；拖牌只在选中、落位时出声，不在指针移动的每一帧播放。
- 只有服务端确认的匹配、入账、结算、特殊牌型等结果才播放成功音。重复 Socket.IO 事件以 `eventId` 去重；断线重连后的旧事件不重播。
- 各音效短、轻、不过度刺激。声音开关、总音量、UI/牌局/通知分类音量由 H5 设置页统一管理；首次用户手势后才恢复 AudioContext，遵守浏览器自动播放限制。
- 声音提供信息冗余而非唯一提示：失败、倒计时、网络状态等必须同时有可见文字/图标。

## 2. 交互到音效映射

| 页面/事件 | 动作与反馈 | 音效复用建议 | 优先级 |
| --- | --- | --- | --- |
| 全局按钮 | 主按钮点击、次按钮点击、禁用按钮反馈 | `ui-tap`、`ui-back`；禁用时不播放或轻微 `ui-deny` | 必须 |
| 导航与弹窗 | 切换大厅/子厅/档位/个人页，打开/关闭弹窗 | `ui-open`、`ui-close`；页面切换只用极轻短音，避免连点堆叠 | 必须 |
| 控件 | Tab 选择、单选档位、开关、复选框、滑杆调整 | `ui-select`、`ui-toggle`；滑杆拖动不逐帧发声，只在吸附刻度或松手时反馈 | 必须 |
| 操作状态 | 成功确认、校验失败、无权限/金币不足、复制链接成功 | `ui-confirm`、`ui-error`、`ui-copy` | 必须 |
| 游戏卡片/子厅 | 卡片选择、进入十三张子厅、选择难度厅、返回 | 复用 `ui-select`、`ui-enter-game`、`ui-back` | 必须 |
| 匹配/房间 | 开始/取消匹配、匹配成功、创建/加入房间、玩家加入、准备/取消准备 | `match-search`（可无声）、`match-found`、`room-join`、`room-ready` | 必须 |
| 大厅通知 | 收到系统通知、邀请、客服新消息、好友/玩家上线状态 | `notification`；同类通知短时间内合并，不每个在线状态都响 | 必须 |
| 钱包/资产 | 充值订单成功/失败、转账发出/收到、兑换、提现申请/审核结果 | 中性 `transaction-ok`、`transaction-error`；不因金币数额大小改变音量 | 必须 |
| 客服 IM | 发送消息、收到客服新消息、图片上传/发送成功或失败 | `message-send`、`message-received`、复用 `ui-confirm/error` | 必须 |
| 连接状态 | 弱网/断线、重连成功、会话失效 | `connection-warning`、`connection-restored`；仅状态边沿播放一次 | 必须 |
| 洗牌/发牌 | 开局洗牌提示、13 张牌依次飞入 | `card-shuffle`、`card-deal`；做 3–4 个轻微变化，连续播放时限幅 | 必须 |
| 理牌 | 选中/取消选牌、拖到墩位吸附、调整顺序 | `card-pick`、`card-place`；拖动过程不出声 | 必须 |
| 牌组操作 | 自动理牌完成、撤销、清空、提交牌组 | `auto-arrange`、复用 `ui-back`、`ui-clear`、`hand-submit` | 必须 |
| 等待与超时 | 进入最后 5 秒倒计时、最后 3 秒提示、超时自动提交 | `timer-tick` 的弱/强两级；只响最后几秒，不整段倒数 | 必须 |
| 翻牌比牌 | 头/中/底墩依次公开，播放胜/负/平结果 | `card-reveal`、`compare-win`、`compare-loss`、`compare-draw` | 必须 |
| 特殊计分 | 头墩三条、中墩葫芦/铁支/同花顺、底墩铁支/同花顺 | 复用 `special-score`，按分值/牌型最多分强弱两级；只在该局对应配置开启时播放 | 按规则配置 |
| 打枪/全垒打 | 服务端判定全胜与全场大胜 | `slam`、`full-sweep`，只在规则开关开启且结算确认后播放 | 按规则配置 |
| 相公/特殊整手 | 判定倒道、全手特殊牌型等可配置规则 | `foul`、`special-hand`；仅启用对应规则时播放 | 按规则配置 |
| 结算 | 最终积分/金币变化、返回大厅 | 复用 `round-win`、`round-loss`、`transaction-ok`、`ui-back`；避免将每墩胜负声连续叠满 | 必须 |

桌面浏览器按钮 hover/focus 可使用极轻反馈音，但默认仅 hover 不播，键盘 focus 不重复播点击音。大厅入口、钱包、充值、战绩、设置、邀请、个人资料和客服按钮均复用同一组 UI 声音，不为图标分别制作素材。

## 3. 首批独立音源规模

按上表有 36 个语义音色键；UI 转场、选择/开关、房间状态和比较结果等可共享母音色，初步估计 **24–30 个基础母音源**。动画变化和不同音量等级由客户端或构建脚本派生，不增加模型请求：

`ui-tap`、`ui-back`、`ui-open`、`ui-close`、`ui-select`、`ui-toggle`、`ui-confirm`、`ui-error`、`ui-copy`、`ui-enter-game`、`notification`、`match-found`、`room-join`、`room-ready`、`transaction-ok`、`message-send`、`message-received`、`connection-warning`、`connection-restored`、`card-shuffle`、`card-deal`、`card-pick`、`card-place`、`hand-submit`、`timer-tick`、`card-reveal`、`compare-win`、`compare-loss`、`compare-draw`、`special-score`、`slam`、`full-sweep`、`foul`、`special-hand`、`round-win`、`round-loss`。

最终母版数以试听为准，不为了凑数生成重复音效。若运行时规则未启用相应玩法，其音效资源不随游戏核心包加载。

## 4. AI 音效生成方案

**首选 ElevenLabs Sound Effects API**。它提供专门的文字转音效端点，文档列出游戏/互动媒体用例，支持提示词、时长、循环控制及生成音效；比把语音模型改作音效生成更合适。API 文档中的 `eleven_text_to_sound_v2` 时长范围为 0.5–30 秒，默认返回 MP3。短 UI/牌局音效应按目标时长单条生成，避免为一个按钮音效生成长音频后再裁切。[Sound Effects API](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert) [Sound Effects 能力说明](https://elevenlabs.io/docs/overview/capabilities/sound-effects)

先做三条试样：轻触按钮、卡牌落桌、胜利提示。检查是否夹带人声/音乐、瞬态是否干净、尾音是否适合裁切或循环，以及同一套音色能否由提示词稳定复现。确认风格后，再按本清单的音效 ID 批量制作；小幅变体优先通过剪辑、音高和声像变化派生，减少重复生成。批量前查看账户当期 API 价格和套餐授权，价格以控制台及当时条款为准。

**备选：Stable Audio 3.0 Small SFX 自托管**。它是面向音效的开放权重模型路线，适合未来需要本地批量生成、减少逐次 API 调用或加强制作管线控制时评估；需要自行承担部署、推理、质检和模型许可核验。Stable Audio 的许可对组织年收入设有门槛（超过 100 万美元需企业许可），上线商用前必须按实际主体与模型许可确认。[Stable Audio 3.0 模型家族与许可说明](https://stability.ai/news-updates/meet-stable-audio-3-the-model-family-built-for-artistic-experimentation-with-open-weight-models)

OpenAI 仍可用于提示词整理、音效分类和台账生成；其当前公开音频接口文档主要描述语音合成、转录/翻译和语音对话，没有专用的非语音音效生成端点。因此不将 TTS 模型当作卡牌、按钮或提示音生成器。[OpenAI Audio 文档](https://developers.openai.com/api/docs/guides/audio) [OpenAI Text to speech 文档](https://developers.openai.com/api/docs/guides/text-to-speech)

生成 API 密钥只放在内部素材执行端的环境配置中，不进入 Git、浏览器客户端或公开资源清单。台账记录提供方、确切模型 ID、提示词、原始输出、许可/套餐、生成日期和实际费用。

## 5. 母版、编码和浏览器播放

生成服务返回音频后，同时保留原始下载文件和 WAV PCM 工作母版（建议 48 kHz、24-bit；如果原始文件为 MP3，转成 WAV 只是便于编辑的 PCM 工作副本，并不会恢复已丢失的音质）。剪辑/降噪/淡入淡出只在工作母版上执行，运行时编码从工作母版派生，避免多代有损重编码。

用户提出的 **HE-AAC v2 双声道**适合较低码率的立体声长音频，但不建议作为整站音效唯一编码：浏览器/Chromium 构建对 AAC profile 的支持不完全一致，HE-AAC v2 需要额外确认解码器和 WebAudio `decodeAudioData` 行为。绝大多数按钮/卡牌瞬态也不需要双声道；用单声道素材，再由 Web Audio 按座位位置做声像即可。

推荐运行时主格式为 **Opus（WebM 或 Ogg 容器）**：短音效用单声道、24–48 kbps；较复杂的庆祝/空间音效用 48–64 kbps 或必要时双声道。Opus 对低码率声音压缩效率高、开源无许可费用。当前 MDN 的容器兼容表列出 WebM/Opus 在 Chrome、Edge、Firefox、Safari 中支持，但 Ogg/Opus 的 Safari 支持有较新的系统版本门槛；故按实际目标浏览器测试容器，不能只看 codec 名称。[MDN Web audio codec guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs) [MDN media container compatibility](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers)

兼容策略：构建时输出 WebM/Opus 主档，并在需要支持较旧 Safari/WebView 或解码探测失败时输出 AAC-LC `.m4a` 备档；若特定桌面环境仍不支持，则以 MP3 作兼容末档。启动时使用 `canPlayType`/MediaCapabilities 做容器能力选择；实际 `AudioContext.decodeAudioData` 失败时退到下一档。不要把 HE-AAC v2 profile 当成所有 Chromium 浏览器都能解码的保证。若后续验证目标客户端均支持某一单档格式，再删减备档以节省下载量。

文件组织建议：

```text
assets/audio/
├── masters/                 # 原始无损母版，不进入客户端
├── candidates/<key>/<job>/  # 待审核生成物与编码试听样本
└── release/<hash>/          # 审核通过后才写入发布目录
```

大厅可交互后预载通用 UI/通知音，进入十三张子厅时再按实际开启规则加载牌局音效。常用核心音效可解码进 `AudioBuffer`，通过共享 AudioContext 精确调度；多个小音效可按 UI、桌面动作、结算分包或使用音频 sprite 降低请求数。sprite 的时间偏移需基于最终编码/解码文件校验，不能直接沿用 WAV 母版的样本位置。后台闲时预取遵守现有网络调度器，弱网时先保证 H5/Pixi 首屏；音效文件失败不阻塞大厅/牌局。

应用设置保存全局静音、UI、牌局、通知音量。浏览器通常要求用户手势后才能启动音频，登录页不主动响铃；恢复上下文失败或用户静音时保持无声，不影响游戏操作。多声部同时触发应限制最大并发声源、单事件重复间隔与总线峰值，避免连续发牌和结算时刺耳或削波。

## 6. 验收

- 首次用户操作后音频上下文可用；未操作、静音和音效资源未加载时无异常。
- 常见移动端 Safari/WebKit、Android Chromium、桌面 Chrome/Edge/Firefox/Safari 与五端封装 WebView 分别试播主档及回退档。
- 单音、同事件快速重复、发 13 张牌、结算连播时都无爆音、明显削波、重复通知或长尾残留。
- 牌局规则音效只受服务端确认结果和该局 `game_config` 快照控制；玩法关闭时不播放、不加载。
- 清单中的大厅按钮全覆盖；同语义按钮共用音效 ID，避免产生大量仅差几毫秒的独立资产。
- 每个素材台账记录提供方、准确模型 ID、请求提示、原始输出、许可/套餐、转码命令及参数、原始/成品哈希、码率、声道、时长、尺寸、审核状态和实际费用。
