# 管理后台功能规划

阶段：功能架构与响应式页面规划，供产品审核。后台是独立 **Vue 3 + TypeScript + Vite + Element Plus** 应用，使用 pnpm workspace 管理，并从共享契约包引用 schema、接口类型和常量；通过 Admin HTTP API 调用 backend 用例，不直接访问 Sequelize Model、Redis 或资产账本。桌面端面向高密度运营工作，手机端面向快速查询、审核、客服和告警处理。所有玩家仍统一在 `user` 表，后台操作者也使用 user 身份和常量化 `role_type` 区分，不单独建 `admin_user`。

逐条页面与三级弹窗/抽屉的入口、交互状态、共用组件、共享 DTO、权限边界及闭环清单见[后台与前台页面交互目录](./后台与前台页面交互目录.md)。设计闭环、前端页面实现与真实服务端联调分列记录。当前 Admin 应用已有独立响应式壳、无伪造数据的总览、用户列表/详情、代理域列表、资产操作账本、大厅游戏目录（本机 IndexedDB DDD 演练）、十三张本地规则配置候选与桌级期望模拟、事件规则/实例/公告模板/投递、社区话题/审核、客服队列/会话、Asset 目录/AI 生成台账/资源发布检查、系统配置/权限/审计/任务结构页及接入 `/health/live` 的 API 存活探针、通用商品目录、支付渠道至 Mock 控制台的本机 DDD 演练（订单锁定启用渠道快照、事件不履约）、充值订单证据链、提现审核规则、TRON 监控、外部结算流水和对账异常工作台结构页，以及禁用凭证输入的登录展示页；Agent 另有独立响应式壳和总览，下线列表/筛选/游标分页、查看目的、幂等审计写入、详情 Drawer 及本机审计查询/过滤已通过共享 DTO、DDD 与 Admin 专用 IndexedDB 完成本地演练，域游戏配置/计算、广播、社区/私聊仍待离线闭环；开发演练不代表 Agent 授权或真实数据，不与 Admin 导航/API/授权混用。用户查询与详情读取、代理域审批/capability 操作、账本读取/调账、目录生产 Asset 授权与发布、其他游戏 schema/math report/版本发布、事件查询与命令、社交内容/客服消息授权读取与命令、附件授权解密、资源目录/内部生成执行端/发布、系统配置读取写入、Admin 权限读取授予/撤销、审计查询、任务查询重试、依赖健康遥测与历史、商品读取与履约、生产支付 channel/provider API、订单时间线/真实履约、提现审核/出款和占款查询、链事件读取/确认和客服处置、外部结算读取/handler 校验、对账案件读取/处置、Agent 域解析/capability/其他业务页面及 Admin API 尚未实现。十三张本地试算不等于服务端模拟 worker 或配置发布。Mock 控制台仅模拟本机测试订单与事件状态，不请求 provider/生产订单服务、不入账，不能作为真实支付集成。

Admin 客服坐席现在有独立本机演练闭环：基于共享 Support DTO 和 DDD application，支持队列筛选、会话历史、领取、文本回复、结束/重开及刷新恢复；附件因为统一 Asset 上传、授权解密与审计尚未实现，保持关闭。Admin 坐席本机数据与玩家侧客服会话 IndexedDB 隔离，LOCAL_DEMO 示例不代表真实工单。其页面/命令边界与剩余服务端依赖见[客服 IM 与用户工单设计](../04_domains/客服IM与用户工单设计.md)。

Admin 社区审核也有共享 SocialModeration DTO 的本机 DDD 演练：支持待审/举报查询、cursor 分页、正文与举报摘要、通过/隐藏/恢复/驳回、原因校验、幂等重试和追加式审核历史。演练数据与玩家社交内容隔离；topic 目录编辑仍未实现。生产 Admin capability、代理域授权、MySQL 审核事务及公开内容 Asset 处理待服务端/Asset 能力接入。

Admin 权限页现有共享 `AdminPermissionPathDto`、统一 user 权限 DTO、变更命令/响应及审计 DTO；本机 DDD 用例通过 IndexedDB 完成账号筛选、登记的 HTTP method/path 授予/撤销、变更差异确认、理由校验、幂等重放、`auth_version` 递增与权限审计追加。LOCAL_DEMO 只验证浏览器流程；API 路由注册、权限 middleware、真实 JWT 撤销、服务端持久化和服务端审计仍待实现。操作审计页现有共享 `AdminAuditDto` 只读投影，将已有权限、代理域审核、游戏目录、支付渠道、公告模板和社区审核领域审计统一筛选分页并查看安全摘要；投影直接读领域 stores，不复制持久化数据。离线命令当前只写成功操作，拒绝/失败的审计事实仍待命令用例实现；Worker/Outbox 仍是结构页。

Admin 用户列表和详情页已使用共享 `AdminUserQueryDto`、摘要及按分区判别的详情 DTO，通过 DDD application/use case 读取；本机使用明确标记的 `LOCAL_DEMO` 合成目录，支持用户 ID/用户名、角色/状态过滤、游标分页和六个独立详情分区。详情只提供联系方式掩码、安全摘要、邀请祖先、资产及账务摘要、已结算牌局摘要、社交审计元数据，不提供凭证/恢复码/设备指纹/私聊正文或写操作。此本机适配器不访问玩家侧数据库，也不伪装线上用户；生产 Admin API、按分区 capability 授权和真实服务端查询仍待实现。

Admin 房间观察与战绩/回放采用共享 TypeBox DTO 与 DDD application；本机只读 adapter 通过合成快照走通游戏/难度/状态、玩家/日期等筛选、游标加载、详情读取。房间详情取 `room`/`room_membership` 的平台通用快照；牌局详情取 `round`/`round_player`/结算与 asset operation 引用。handler 私有 JSON 只允许由对应版本 renderer 解释，平台只展示安全摘要，不修改历史结算。演练不写真实房间、牌局或账本；生产 Admin capability、Redis/MySQL 查询和 handler 解释器仍待接入。

Admin 邀请关系页以共享 `AdminReferral*Dto`、领域 application 和单个 Admin IndexedDB 聚合快照完成本机换绑演练。页面提供绑定筛选、四级祖先详情、不可变历史返佣、换绑事件、影响预览和社交迁移任务处理。应用层验证目标、自环/祖先环、预览版本、原因和演练 TOTP；本机单事务重算所有受影响当前链、清零当前绑定收益投影并追加事件/迁移任务，历史返佣分配保持原样。离线存储仅追加一个 `admin_referral_workspace_snapshots` object store（Admin DB v11），关系、历史、任务和幂等回执作为一个领域聚合保存，不照搬生产 MySQL 表。固定演练码只用于 `LOCAL_DEMO` 页面闭环；完成迁移按钮只更新合成 task 状态，不读取或移动真实社交数据。生产 Admin capability、服务端 TOTP、关系/审计/outbox 同事务及社交迁移 worker 仍待实现。

## 1. 设计原则

- **以运营任务组织菜单**：围绕玩家、资产、游戏、配置、社区、客服和系统运维组织，不把表名直接变成菜单。
- **查询与执行分离**：浏览详情、导出、调账、封禁、发布配置、处理提现等是不同权限路径；高风险写操作要求确认理由并记录审计。
- **后台配置不越过领域规则**：资产调整调用 wallet 用例；游戏参数通过 schema、期望计算器及版本发布；事件/广播调用平台事件服务；社区处理调用 social moderation；不能在 Admin 页面直接改表。
- **配置先预览后发布**：展示影响范围、生效版本和回滚方案。游戏局/投注开始后锁定配置快照，后续配置只影响新局。
- **生产/测试清晰隔离**：支付 Mock 页面与 Mock Provider 只在开发/测试环境启用，生产构建和 API 均拒绝测试操作。
- **隐私与授权最小化**：客服会话、社区公开内容、私聊、身份凭证和支付资料具有不同权限；看到某一类内容不意味着可以看其他类别。

## 4. 功能域与首版范围

### 4.1 总览与可观测

- 在线数、平台/游戏 Socket 连接、匹配队列、房间数、游戏局阶段、事件广播状态。
- 钱包/充值/提现异常队列数量和延迟；不在总览显示明文支付凭证。
- worker/outbox 积压、失败重试、资源生成/发布任务状态。
- 所有指标显示更新时间和采样范围；支持按游戏/难度/区域过滤。

### 4.2 用户、代理与资产

- 用户搜索：user ID、公开用户名、设备摘要、邮箱/手机掩码；敏感字段需单独 permission path。
- 用户详情：常量化 `role_type/reward_type/status`、直属上级和最多四级祖先、设备/凭证概况、冻结/限制状态、用户报告入口。
- 资产视图：余额、金币、冻结/占用、流水要求状态、按 asset_operation 关联的完整分录；展示不可变流水，不允许后台直接编辑余额。
- Admin 调账：输入资产类型、金额、方向、原因和工单号；展示执行前后余额与对应系统账户分录，强制二次确认并记录操作者。批量发放必须走独立授权和额度控制。
- 邀请/返佣：关系链及各级获利配置、充值返点冻结/解冻状态、返佣记录查询。客损模式由代理线下结算，后台不出现平台“客损返佣结算”按钮。
- 代理域：生产端审核代理申请、分配/撤销 capability codes、暂停/恢复域；前端当前提供明确标记的 `LOCAL_DEMO` 审核流程，演练身份和数据只留在 Admin IndexedDB。Agent 下线管理已离线闭环搜索、筛选、翻页、查看目的、详情及追加式审计，并能按目的/资源查询审计；生产 API 必须由服务端原子校验 `user.role_type`/域/capability，审计落库后才返回详情，并保证越域拒绝。授予 `AGENT_DOWNLINE_READ` 后可查看直接管理范围业务明细（资产、支付、游戏、邀请及流水，不含认证秘密）；授予私聊读取能力后可查看本域私聊，访问留审计。父域不得读取子域私密明细。
- 换绑：只有指定权限可操作；必须输入 TOTP 并填写原因，保留旧关系与审计，向相关账号推送安全通知。
- 封禁/解封/限额：采用明确状态转换、理由、有效期及解除审计，不以物理删除代替状态。

### 4.3 游戏目录、房间与规则配置

- 管理游戏目录名称、cover asset、排序、开放/维护状态和子厅入口。
- Admin 浏览器本机演练以共享 `GameCatalogDto` 为输入：编辑目录字段时须通过 TypeBox 请求校验、引用可选封面、填写原因，并在 IndexedDB 同事务保存新目录快照和追加式变更记录；此演练不会发布生产配置。
- 内置/外接 Stub 均只能由可信构建注册表确定是否可进入；新增外接 Stub 缺少 `clientModuleKey` 且 `isPlayable=false`，不解析远端代码地址。玩家大厅和 Admin 的生产目录统一由服务端 API 提供，不能把各自浏览器的 IndexedDB 当成跨站共享存储。
- 按 `game_key + difficulty_key` 查看准入上下限、底分/下注档、规则开关、活动参数、机器人档位及版本状态。
- 代理域配置作为有硬边界的局部 override；代理对显式开放的参数运行期望计算器，通过边界校验后即时发布本域版本，不能修改平台基准或其他域配置。
- 配置编辑器只展示该游戏 schema 允许的字段；不接受任意 JSON 脚本。
- 配置差异、影响范围、期望计算报告和上线时间完整记录；新增版本只影响新局/新投注。
- 房间管理支持查看状态/成员/重连信息、结束异常空房、封禁违规用户；不得让后台人员更改已结算牌局结果。
- 战绩查询展示游戏 handler 提供的通用 session summary 与游戏专属 JSON 明细；管理员只读，不由通用后台解释各游戏内部 payload。

### 4.4 期望计算器

这是高风险配置前置工具，不只是报表页面：支持精确计算、1000/10000 局模拟、结果分布、模拟实际 RTP、轮空率、大奖率、方差、标准差、置信区间及候选参数优化。详细口径见[游戏期望计算器与参数优化设计](../03_game_systems/游戏期望计算器与参数优化设计.md)。

后台要区分 `theoretical` 与 `observed simulation`；显示模型未实现、低样本、罕见奖项样本不足、候选无解等状态。自动优化不得直接发布，也不能根据真实用户最近输赢自动调整概率。

### 4.5 活动事件与全局跑马灯

- 配置 event type、来源游戏/难度、阈值 schema、事件触发者类型、受众范围、主体排除、脱敏模板、有效期和席位上限。
- 对活动效果选择 `broadcast_only`、公开奖池奖励或经数学审核的 odds profile；不同游戏只使用自身已登记 effect handler。
- 预览公告在大厅/子厅/牌桌的版式，必须显示实际概率/派奖变化、适用范围、开始/结束条件；纯公告不得写成概率加成。
- 查看实例状态、真实席位占用、池余额/预留、触发来源、投递/失败及版本；不允许编辑已发实例的历史结果。
- 手动触发/取消仅给特权操作员，必须指定原因；生产环境可默认关闭手动触发。
- 模板使用安全占位符和脱敏昵称策略；主体本人排除由服务端受众过滤执行。

Admin 事件与公告已有本机纵向演练：共享 DTO、事件 application 与单个 IndexedDB 聚合快照支持规则新增/启用、合成事件校验与取消、LOCAL_DEMO 实例、PREVIEW_ONLY 文案及追加审计；规则页触发会转到实例页打开输入弹窗。此演练与公告模板草稿彼此独立，预览当前使用固定安全文案，不冒充已应用模板。没有服务端事件事实时绝不声称真实席位、奖池、概率效果或 Socket 送达；生产 capability、事件/outbox worker、代理域隔离、模板发布、真实公告投递与重试仍待后端。

### 4.6 社区与客服

- 话题目录：新增/编辑名称、说明、封面 asset、排序、启用状态；变更记录版本和操作者。
- 社区审核：帖子/回复待审、举报队列、隐藏/恢复/置顶到期、处理备注、用户封禁建议。
- 社区通知/公告由独立平台事件模板发送；不要把社区审核员权限扩展到私信内容。
- 客服 IM：队列分配、会话接管/转交、用户身份摘要、回复模板、附件授权解密、解决/关闭状态；客服文件保留期按既定配置。读取用户上传附件每次都要记录授权客服、目的、asset ID 和时间。
- 账号安全工单支持 TOTP/恢复凭证异常的人工核验；后台不能直接重置用户 TOTP。用户无法重置，需客服人工流程。

### 4.7 商品、支付与提现

- 通用商品维护（不局限金币商品）、价格、交付资产、可购买状态和版本。
- 支付方式管理排序和展示；首版实际通道以 Mock Provider 为主，但提供仅开发环境可用的 Mock 控制台：模拟成功/失败/超时/重复回调/金额错误。
- 充值订单与外部 T 型结算流水分别查看，通过 `order_id`/业务引用关联；支付回调及 handler 校验状态迁移，不能手动伪造“已支付”绕过入账用例。
- TRON 订单查看收款地址、应收唯一金额、链上交易、确认数、超时和人工异常；私钥不可在后台界面展示/导出。
- 提现审核展示实际到账金额、向上取整手续费和金币扣款，接受/拒绝通过业务用例执行；线下出款处于审核通过后待处理/三天窗口状态时保留操作审计。
- 对账异常只能进入处置工作流，不能直接改外部结算历史行。

### 4.8 素材与 AI 资源

- 查看素材 asset、格式/质量 variant、版本、大小、哈希、来源、审核状态和使用位置。
- 创建 AI 生成任务时选用已锁定模型配置/风格规范；API token 只在内部素材执行端，Admin 浏览器不接触密钥。
- 生成任务成本、提示词版本、模型/图像模型 ID、输出结果和审核人进入素材台账；批准后才能绑定游戏 cover/大厅插画/动效并进入 manifest。
- 资源发布前运行格式、体积、尺寸、透明背景、变体完整性与文件校验；大图/动画发布显示带宽影响。

### 4.9 系统配置、权限与审计

- `system_config` 与 `game_config` 分开展示；每项显示 config type、解析器、默认值、当前值、影响范围和密钥/敏感标记。密钥类值不回显。
- 当前浏览器离线施工阶段仅提供需求参考值与候选草稿：草稿保存在 Admin 专用 IndexedDB `gameing_hall_admin_dev.system_config_drafts`，重载页面后可恢复；保存/撤销只改变本机草稿，不改变生效配置。生产读取、权限、审计、发布和即时生效必须通过 Admin API/application 流程完成。
- Admin 账号仍是 user；采用最小 permission path 集合。按此前方案可在 user 权限 JSON 中保存授权路径，后台维护权限模板时只组合已登记路由，不允许录入任意路径。最终字段与数据规则以数据库 SDD 校准。
- 权限检查放在 API/service handler，按 HTTP method + normalized route path（及必要的 resource scope）验证；前端菜单权限仅用于显示。
- 高风险权限分离：资产调账、支付审核、游戏配置发布、事件手动触发、社区审核、客服附件解密、权限管理互相独立；敏感操作可要求 TOTP 和二次审核。
- 审计记录操作者 user ID、permission path、目标实体、前后值摘要、理由、请求 ID、时间和来源；不可变，不提供普通删除功能。

## 8. 登录与可选 TOTP 页面

此方案已有明确支持；`OTOP` 通常是 `TOTP` 的笔误。普通玩家和 Admin 都可以自愿启用 RFC 6238 兼容的 TOTP，不强制启用。Admin 使用独立 JWT audience 和 Admin 权限校验；TOTP 是账号附加验证，不替代 Admin authorization。

### 8.1 Admin 登录

```text
┌──────────────────────────────┐
│         管理后台登录         │
│ [用户名/邮箱____________]    │
│ [密码___________________]    │
│ [登录]                       │
│                              │
│ 若账号启用 TOTP：             │
│ [Authenticator 验证码 ____]  │
│ [验证并登录]                 │
└──────────────────────────────┘
```

是否要求高权限 Admin 必须启用 TOTP目前按既定决议为“自愿”，不在页面暗中强制。组织策略若未来改为强制，需作为单独业务决议和迁移计划，不由前端自行判断。

### 8.2 安全设置启用流程

```text
安全设置 → 两步验证（TOTP）
当前状态：未启用
[启用]
  → 重新输入密码/当前身份验证
  → 显示一次性二维码和手动密钥（仅此时显示）
  → 用户在认证器输入 6 位验证码
  → 服务端验证成功后启用，并显示一组一次性备用恢复码（仅展示一次）

当前状态：已启用
[查看剩余恢复码数量]
[重新生成恢复码] → 当前密码 + 当前 TOTP → 旧码全部失效，显示新码并通知用户
[关闭] → 当前密码 + 当前 TOTP → 关闭并记录安全事件
[遗失认证器？联系客服] → 创建客服安全工单
```

TOTP secret 只在首次绑定确认前暂存 Redis，确认后加密保存。启用时产生一组一次性恢复码，只展示一次；登录挑战可用一条码替代当次 TOTP，并原子消费。恢复码不能用于重置/关闭/重绑 TOTP，也不能替代账号恢复二维码流程所要求的当前 TOTP。遗失认证器时由客服 IM 发起人工核验，Admin 处置必须关联客服会话及审计。规则详见 [JWT 登录与会话设计](../04_domains/JWT登录与会话设计.md)。

## 9. 页面实现与响应式验收

- Vue 页面共享业务 feature 和 contracts；Element Plus 组件按需加载。桌面与手机布局用 CSS/Grid/容器断点适配，不复制两份路由/权限代码。
- 列表支持 URL 可恢复筛选条件（敏感搜索词除外）、服务端分页、稳定排序和清晰空态；手机列表改为卡片/详情，不丢失状态或操作反馈。
- 关键操作在 320 CSS px 窄屏、200% 缩放、键盘导航和触屏目标尺寸下可操作；不依靠 hover 展示唯一操作入口。
- 生产、测试环境常驻可见；页面切换、横竖屏旋转和后台恢复不重复提交管理命令，所有写操作带幂等键。
- Admin 登录、TOTP 挑战/启用/关闭、权限拒绝、过期 JWT、客服人工恢复等均有桌面/移动 E2E 场景；截图只验证布局，不替代 API 权限测试。

## 10. 后端边界与数据依赖

- Admin app → Admin HTTP API → backend application services → domain repositories。管理 UI 不直连 DB/Redis，也不复用玩家端 store。
- 需要实时更新的房间、订单、事件和客服队列通过管理端 Socket.IO 订阅通知；重要内容始终可 HTTP 拉取重建。
- 计算器 worker 无生产账本写权限；支付 Mock handler 有环境隔离；AI 素材 token 只在内部执行器。
- 资产操作、支付状态变化、配置发布、社区审核、客服授权、权限变化走各自领域用例，并写统一不可变审计/outbox。
- Admin API 使用独立的 route namespace 和 permission path；JWT 仍是 user 身份凭证，admin capability 服务端每次授权，不相信客户端 `role_type` claims 的旧快照。

## 11. 交付阶段

### 阶段 A：安全可运营基础

Admin 登录/能力、审计、用户查询、资产流水只读、游戏目录/难度配置草稿、配置校验、期望计算器、发布审批、支付 Mock 控制台。

### 阶段 B：平台运营

事件与跑马灯后台、社区话题/帖子审核、客服 IM 工作台、商品/充值/提现与 TRON 监控、AI asset 管理。

### 阶段 C：规模化运维

多维报表、批量操作审批、细化风控队列、发布灰度/回滚、告警路由、审计归档和权限定期复核。

阶段顺序可重排，但资产、权限、配置发布、支付和模拟器的服务端规则必须先于相应的可操作 Admin UI。

## 12. 验收底线

1. 所有管理 API 服务器端鉴权；无权用户直接调用 API/Socket 仍失败。
2. 资产、支付、提现、配置发布、事件手动操作、权限和附件解密均有理由、操作者和不可变审计。
3. Admin 不能直接改资产余额、已结算牌局和外部结算事实。
4. 期望计算器只产生模拟报告/候选；配置发布明确展示版本和影响的新局范围。
5. 支付 Mock 不能被生产配置启用，Mock 状态不能生成生产可提现资产。
6. 客损直属上级导致玩家社交不可用，与 Admin 社区审核能力分离；客服不可默认读取社交私聊。
7. 话题、帖子审核和客服会话具有不同的数据权限，社区审核员无法通过通用搜索读取客服/私聊数据。
8. 敏感凭证、TOTP 秘密、JWT、支付密钥和 AI API token 不回显、不进入日志或导出。
