# 交互引导需求分析与 UI/UX 设计

版本：0.1（需求分析与体验设计稿）  
目的：在既有后台、代理工作区、玩家大厅、子厅和牌桌交互设计上，补齐用户“此处能做什么、下一步是什么、结果会怎样”的引导。本文先分析需求，再定义引导模式、页面内容和验收清单；不替代领域规则、支付/账务 SDD 或游戏玩法规则。

## 1. 需求分析

### 1.1 体验问题与目标

项目同时包含休闲游戏、真实资产操作、社交/客服、代理域和高风险后台配置。用户若只看到按钮和字段，容易不知道流程入口、费用/限制、状态变化和失败后的安全操作；Admin/代理操作者还可能误判权限范围、RTP 报告或配置生效范围。引导需要降低首次使用门槛，并在高影响动作发生前帮助用户理解后果。

本轮体验目标：

1. 首次进入大厅时，用户能在短时间内知道如何选游戏、选难度、开始牌局及找到钱包/客服。
2. 每个重要操作入口附近提供就地解释；不要求用户先完成一段强制新手教程。
3. 资金、账号安全、邀请归因、代理域权限、概率配置等信息必须在决策点解释，不能只靠可忽略的首次引导。
4. 用户关闭或跳过引导后仍能完成操作，并能从“帮助/玩法说明”重新打开。
5. 说明内容与服务器实际状态一致；不创造虚假名额、概率加成、奖励承诺或“马上就结束”的催促。
6. 手机、桌面、触屏、键盘和 PixiJS 牌桌上的引导都可读、可退出，并且不挡住关键操作。

### 1.2 用户与主要任务

| 用户 | 主要认知任务 | 容易出错的节点 | 必须出现的解释 |
| --- | --- | --- | --- |
| 新玩家 | 认识大厅、子厅、难度和开局路径 | 把难度理解为装饰等级；误以为“匹配”已扣款/已入座 | 进入门槛、底分/下注、可用余额校验、匹配确认状态 |
| 常驻玩家 | 快速找到资产、战绩、邀请、社区和客服 | 混淆金币与余额、可用与冻结、页面通知与最终状态 | 资产单位、冻结原因、状态更新时间、服务端结果查询 |
| 十三张玩家 | 理解三墩、倒道、提交、断线恢复和结算 | 不理解中墩/底墩比较或倒道全赔；弱网时重复提交 | 玩法说明、提交锁定、错误定位、重连快照、逐墩结果 |
| 内容/社交用户 | 发帖、跟帖、私信、发送加密附件 | 误判公开范围、代理域范围、附件授权 | 可见范围、域归属、附件密钥授权及换绑迁移影响 |
| 代理 | 理解代理域、下线明细范围、权限和即时生效配置 | 以为能查看子代理域私密明细或全平台数据 | 当前域范围、能力边界、RTP 参数边界、审计记录 |
| Admin/运营 | 查询、审核、改配置、看计算器并发布 | 误把模拟当生产结果；误以为保存就是生效；误用高权限 | 环境、数据时间、配置版本、模拟/理论区别、发布影响与回滚 |
| 客服 | 接单、回复、授权看附件、转人工核验 | 把客服授权当作任意读取权限，或误认为可重置 TOTP | 会话范围、附件逐次授权、不可执行的安全处置及升级路径 |

### 1.3 引导触发优先级

不是每个字段都需要弹窗。引导按“需不需要打断”分级：

| 级别 | 模式 | 适用 | 是否阻断 |
| --- | --- | --- | --- |
| P0 | 必要规则/风险摘要 `PreflightSummary` | 支付、转账、提现、账号恢复、提交牌局、发布配置、换绑、授权私聊/解密附件 | 用户确认前阻断对应命令；不阻断离开/取消 |
| P1 | 首次轻量导览 `CoachMark` | 首次进入大厅、首次进入某个游戏子厅、首次访问 Agent/Admin 工作区 | 可跳过；不连续强制弹多个步骤 |
| P2 | 就地提示 `InlineHint` / `FieldHelp` | 规则字段、资产单位、配置参数、房间入口、空态说明 | 不阻断；可展开/收起 |
| P3 | 帮助页/玩法说明 `HelpDrawer` | 详细规则、FAQ、术语、例子、弱网说明 | 用户主动打开；能从相关操作回到原位置 |
| P4 | 异常恢复引导 `RecoveryBanner` | 离线、命令结果未知、资源下载失败、会话过期、Socket 重连 | 仅阻断依赖该状态的命令；显示安全恢复动作 |

### 1.4 内容与状态的权威来源

- 资产数、费用、冻结、流水门槛、提现资格、邀请关系、游戏准入、真实席位、事件效果和配置版本从服务端 DTO 读取；说明文字只负责解释，不自行计算权威数值。
- 静态教程和玩法解释随页面/游戏模块版本管理；游戏玩法的启用状态、规则版本以服务端 `GameRulesDto` 为准。
- 可运营调整的解释文案只允许在已登记的 `system_config`/`game_config` schema 中配置安全文案 key 和变量，不开放任意 HTML、脚本或动态 URL。发布前需预览 PC/Mobile 与明暗/高对比场景。
- 引导完成状态首版保存在本机（按 guide key + content version）；可从帮助入口重新播放。关键规则/财务摘要不因“已看过”而省略。跨设备同步进度暂不需要新增表。
- 关闭/跳过引导不产生游戏操作、不接受资金命令、不改变权限，也不发送通知。帮助曝光分析若启用，只记聚合事件，不记录输入内容、资产数值、私聊文本、联系方式或凭证。

### 1.5 业务边界和误导风险

- 跑马灯必须由平台事件和公告 DTO 驱动。只有真实生效的事件才展示概率/派奖变化；纯播报明确写“仅事件播报”。席位文案只有服务端真实限额和实时占位数据才能显示。
- 中奖概率/期望引导展示经审核的配置说明和适用范围，不对玩家暗示可以通过技巧保证中奖，也不把历史短期结果说成未来概率。
- Admin 期望计算器明确标注“模拟结果，不代表未来每一局”；显示轮数、seed、模型/配置 hash、分布、实际 RTP、轮空率、大奖率、方差和样本不足提示。
- 资产操作确认页逐项列出操作资产、到账/扣除、手续费、冻结/审核状态。不能使用只显示“继续”的含糊确认按钮。
- 客服和代理权限提示描述谁在什么条件下能看哪些数据；不能让隐私提示本身泄露玩家所属客损模式或代理身份。

## 2. UI/UX 设计

### 2.1 引导体验原则

1. **先让用户做事，再补解释**：默认展示轻量界面；在正确时机出现一条指引，而不是首次登录一次性讲完整个平台。
2. **一屏一个重点**：CoachMark 每步只解释一个控件/决策；建议 2–4 步，提供“跳过”和“下一步”，不自动跨页面。
3. **就地说明优先**：在费率、准入、继承关系、模拟报告等内容旁放简短提示；长解释进入 Drawer/帮助页。
4. **说明后果，不施压**：使用中性、准确的语言；禁止倒计时式催促、虚假稀缺、伪造其他玩家行为或把营销语句当规则。
5. **每条引导可恢复**：关闭后有明确的“？”、“玩法说明”或“帮助”入口。系统帮助入口始终可达。
6. **尊重操作连续性**：弹窗/Drawer关闭后回到原页面、原筛选和原滚动位置；教程不得抹掉表单草稿。
7. **引导焦点有去处**：首次展示或用户主动重看时，焦点进入“下一步”；跳过/完成后回到游戏卡带。
7. **减少视觉噪声**：默认只显示当前任务相关帮助；避免多个 Tooltip、跑马灯和新手遮罩同时争夺注意力。

### 2.2 共用 UI 组件

| 组件 | 视觉/交互规范 | 典型用途 |
| --- | --- | --- |
| `CoachMark` | 半透明遮罩、聚焦框、短标题/两行说明、步骤点、跳过/下一步；不覆盖目标本身；PC 键盘可聚焦 | 首次大厅、首次子厅、后台第一次配置流程 |
| `InlineHint` | 说明图标 + 单句；点击/触摸展开，键盘可访问；窄屏采用底部提示卡 | 费率、余额状态、权限范围、参数解释 |
| `HelpDrawer` | 标题、目录锚点、例子、相关术语；关闭回原上下文；移动端全屏 Sheet | 玩法规则、提现说明、代理域帮助、客服 FAQ |
| `PreflightSummary` | 核心影响摘要、费用/资格/版本、风险点；明确主确认和取消动作 | 资金命令、牌局提交、配置发布、关系换绑 |
| `EmptyStateGuide` | 解释为什么为空，给一个主要下一步和帮助链接 | 无好友、无记录、无待审任务、没有代理下线 |
| `RecoveryBanner` | 当前状态、最后服务端确认时间、可执行恢复动作；不会把未知状态说成失败 | 离线、重连、命令超时、资源下载失败 |
| `GuideReplay` | 常驻“帮助/重新查看”入口，列出当前页面相关导览和说明 | 玩家设置/玩法说明、后台帮助菜单 |

所有组件从共享 `GuideContentDto`/本地化内容 key 读取标题和说明；变量只能是 schema 登记的安全字段。`GuideState` 只描述本机看到/跳过的内容版本，不进入业务 DTO，不让客户端决定业务权限。

### 2.3 页面引导内容设计

#### 玩家大厅与账号

| 页面/触发 | 引导内容 | 呈现/动作 |
| --- | --- | --- |
| 首次进入大厅 | ①横向滑动选择游戏；②点游戏进入子厅；③钱包、记录、帮助在固定入口 | 3 步 CoachMark；可跳过；设置/帮助可重看 |
| 游戏卡片不可用/维护 | 说明当前开放状态及是否能订阅通知 | 卡片 InlineHint/状态标签；不把占位游戏伪装成可进入 |
| 资产首次打开 | 区分金币与人民币余额；说明可用、冻结、占用和最近更新时间 | 资产 Drawer 顶部短说明；`?` 打开完整资产 FAQ |
| 充值选择 | 支付金额、获得金币、支付方式和订单状态分别展示；离开支付页后可从订单继续查看 | 商品确认摘要；支付回调不确定时展示恢复入口 |
| 兑币/转账/提现 | 解释费率、取整、流水/资格限制；显示输入金额对应的最终变化 | 每次命令必经 PreflightSummary；服务端 quote 失效时重新预览 |
| 身份恢复/换绑/TOTP | 说明哪些凭证会撤销、旧联系方式何时可复用、TOTP 丢失如何联系客服 | 分步帮助 + 确认前摘要；恢复码只展示一次并提醒离线保管 |
| 社交入口被限制 | 统一提示“此功能当前不可用”，给帮助/客服入口，不说明具体上游 reward_type | 能力 DTO 驱动的中性空态；深链与菜单一致 |

#### 游戏子厅、房间与十三张牌桌

| 页面/触发 | 引导内容 | 呈现/动作 |
| --- | --- | --- |
| 首次进入子厅 | 难度档位表示练习参数；难度轨道可横向浏览 | 1 步 CoachMark 聚焦难度卡带；详细规则与本地练习边界仍在对应页面/动作处可见 |

| 首次创建/加入房间 | 房间号、密码、邀请范围及开局后离开会发生什么 | 房间帮助 Drawer；加入前展示游戏/难度/房主摘要 |

| 拖牌/切换牌墩 | 当前墩剩余牌数和选中状态明确；触屏拖动外提供点选/移入按钮 | 持续显示 3/5/5 计数；拖拽帮助只首次出现一次 |
| 自动摆牌 | 是推荐排法，不代表最优或已提交 | 预览时显示“采用/继续手动”；确认后仍可编辑，提交另行确认 |
| 提交/倒计时结束 | 展示合法性、提交后不可编辑与服务器收件状态 | PreflightSummary；提交 ACK 未知时使用原 key 查状态，不重复提交 |

| 结算/打枪/高光 | 逐墩展示结果、计分和特殊规则；动效可跳过，结果始终可读 | 结算帮助入口；首次只解释计分摘要，不挡结算动作 |

#### 社交、客服与事件跑马灯

| 入口/触发 | 引导内容 | 呈现/动作 |
| --- | --- | --- |
| 首次进入社区 | 帖子所属话题和代理域决定可见范围；帖子/回复可被举报 | 首次轻提示 + 社区规则 Drawer |
| 首次发图片 | 图片加密上传、上传完成再发送；客服/代理获准后才能查看附件 | 上传前简短隐私说明；失败保留草稿，不泄漏密钥 |
| 首次私信 | 展示会话可见范围；跨域换绑时整段会话随被换绑用户迁移 | 发送前只说明当前域与双方规则，不弹长法律文本 |
| 客服附件查看（客服端） | 本次授权对象、原因和查看范围；每次授权均记录 | PreflightSummary + 目的选择；授权时效由客服附件授权策略约束 |
| 首次看到跑马灯 | 解释公告是系统事件；点击查看实际范围和生效规则 | 单次可关闭说明；“仅事件播报”和真实效果视觉区分 |
| 事件状态变化 | 起止时间、适用游戏/难度/域、奖池余量或真实席位（如启用） | 数据来自事件快照；失效/池耗尽时更新状态，不保留旧效果文案 |

#### Admin 与代理工作区

| 页面/触发 | 引导内容 | 呈现/动作 |
| --- | --- | --- |
| Admin 首次进入 | 当前环境、待办入口、全局搜索、权限菜单和告警 | 3 步 CoachMark；展示环境标识，跳过不影响页面使用 |
| 用户详情 | 可查看字段受 capability 限制；联系方式掩码；敏感命令有审计 | Tab 首次提示 + 字段级权限说明；不显示当前无权获取的数据 |
| 资产流水/调账 | 账本是追加记录；调账创建新 operation，不直接改旧记录 | 页面顶部 InlineHint；调账前 PreflightSummary 展示守恒方向、理由、目标用户和执行人 |
| 代理域 | 域范围决定下线数据；子代理域明细隔离；私聊需独立授权且会审计 | 首次 Agent CoachMark + 常驻域选择/范围面包屑；每个敏感 Drawer 顶部展示 `domain scope` |
| 游戏参数编辑 | 当前层级、父层继承、允许调整范围和配置版本 | 参数旁 FieldHelp；填写时同步校验范围，不允许只在发布阶段才发现越界 |
| 期望计算器 | 理论和模拟分开；1000/10000 局统计受方差和稀有奖项影响；模拟不扣钱不入生产库 | 开始模拟前说明卡；报告顶部固定显示轮数、模型版本、配置 hash、seed、置信区间和样本不足提示 |
| 参数发布 | 即时生效只影响新局；运行中局使用已锁配置；可回滚到审核过的版本 | Publish Preflight 展示 scope、差异、期望指标变化、目标生效范围、审计理由；必须显式确认 |
| 社交/私聊审计 | 授权后查看的域/会话范围与审计留痕 | 每次打开前简短告知；无权时不显示“尝试访问”入口 |
| 客服身份恢复 | 客服只能按核验流程人工协助，不能重置 TOTP 或恢复码 | 安全工单步骤 checklist；缺证据不能标记解决 |

以下后台路由也必须显示与当前任务相关的说明，不要求用户完成另一段全局教程：

| 后台页面组 | 页面内提示与动作前摘要 |
| --- | --- |

### 2.4 视觉层级与响应式行为

- **桌面端**：CoachMark 使用锚点气泡，最大宽度约 360 px；右侧帮助 Drawer 宽度遵循现有 DetailDrawer。多列运营工作台的帮助不遮住关键表格操作。
- **手机端**：CoachMark 靠近屏幕底部或目标区域下方，避开刘海、安全区和软键盘；多步骤讲解使用底部全宽卡，主动作留在拇指可达区。复杂说明进入全屏 Sheet。
- **PixiJS 牌桌**：Canvas 只绘制聚焦描边/装饰，文字、步骤、操作按钮使用 DOM overlay；屏幕阅读器有语义标签，键盘操作可完成同一流程。
- **颜色与动效**：引导遮罩对比充足但不闪烁；避免红绿作为唯一状态指示；动画不循环、不诱导点击，支持减少动态效果偏好。
- **加载与弱网**：静态帮助文本随轻壳/游戏 handler 本地包加载；图片/动画只作增强，不影响帮助出现；没拿到服务端快照时标明“正在确认”，不拿缓存数字冒充最新状态。
- **关闭与返回**：`跳过`结束整个导览，`知道了`关闭当前提示，`稍后`暂存当前步骤；关闭后不改变路由、房间状态、表单草稿或资金命令。

### 2.5 内容模板与示例文案

引导短文案遵循“现在是什么 → 对你有什么影响 → 下一步可以做什么”，一般不超过标题 14 字、说明 60 个汉字；复杂规则拆为短摘要 + 可展开详情。

```text
标题：金币和余额是两种资产
说明：金币用于游戏；符合条件时可按当前配置兑换为人民币余额。冻结或未完成流水的部分暂不可用。
动作：[查看资产规则] [知道了]

标题：模拟报告不是实际牌局
说明：此报告使用当前模型和配置运行模拟，不扣款、不创建正式牌局。低概率大奖可能需要更多样本才能稳定估计。
动作：[查看指标口径] [开始模拟]

标题：发布后新局使用新配置
说明：当前有 12 局正在运行；它们继续使用各自开局时的配置。新版本通过校验后立即用于后续新局。
动作：[查看差异] [取消] [确认发布]
```

上面文案中的金额、局数、配置影响、准入和事件效果须由 DTO 的字段填充；无该字段时不显示猜测值。

## 2.8 大厅首次引导改为蒙层

首次进入大厅的三步引导使用 CoachMark 蒙层，不在欢迎区增加提示条或其他占位控件。蒙层只抬高当前目标的视觉层级，其余界面轻度变暗；引导卡定位在目标附近，并按视口边界切换到目标上方或下方。步骤依次聚焦横向游戏卡带、可玩的十三张卡片和大厅导航。手机导航位于底部时，引导卡放在导航上方；所有位置均使用视口坐标，避免被大厅容器裁切。

遮罩期间用户可通过“跳过”或 Escape 结束；“下一步”进入下一锚点，最后一步完成后将焦点交还游戏卡带。设置中的“重新查看大厅引导”继续保留。引导卡为固定定位，不参与大厅布局，故不会改变欢迎区、卡带及底部工具栏的排版高度。

引导控件盘点结果：大厅的“横向浏览游戏”已是聚焦游戏卡带的蒙层步骤；旧版子厅标题右侧的独立难度说明卡已移除，改为首次进入时聚焦难度轨道的单步蒙层。设置中保留“重新播放大厅引导”入口，不进入主舞台。玩家端发现性引导统一由首次 CoachMark 承载；具体业务解释使用标题旁“？”弹出帮助层，不以说明卡长期占据面板空间。

子厅蒙层在首次访问后记录本机状态，按“开始选择”或 Escape 关闭，关闭后焦点回到难度卡带；低风险发现性说明可被跳过，实际练习边界仍保留在练习流程中。子厅没有单独的常驻“重看引导”按钮，避免为低频说明增加占位；后续可从大厅设置中的帮助/引导入口统一重播。当前宽度 720px 以下产品主流程在大厅游戏卡内选档，因此子厅在手机视口只作为直达/返回兼容页；它使用自然纵向页面滚动，难度轨道仍在组件内部横向滚动。

大厅导览基础流程已在 Vue H5 中实现：首次进入展示三步蒙层，跳过或完成后记录本机状态，设置面板可重新播放；自动展示和主动重看时焦点进入“下一步”，完成或跳过后焦点返回可操作的游戏卡带。子厅首次进入显示聚焦难度卡带的单步蒙层，关闭后焦点回到卡带。Vitest 覆盖导览步骤、目标、关闭、焦点归还与持久化。此次 Headless Chrome 实测子厅：1280×800 时文档为 `scrollWidth/clientWidth=1280/1280`、`scrollHeight/clientHeight=800/800`，引导卡 380×141，难度轨道 1184×409；390×844 直达兼容页文档为 `390/390`、`858/844`，自然纵向滚动 14px，蒙层 358×141，难度轨道 390×281，横向溢出仅在卡带内部。该手机子厅高度是纵向内容布局，不属于主移动流程；大厅移动主页面此前实测为 390/390、844/844。卡带自身按设计横向滚动，不造成页面宽度溢出。真机读屏与系统辅助技术完整验收仍待补。平台公告和依赖房间、资金、社交、身份、后台 DTO 的引导继续等待对应服务，不以本地文本模拟业务成功。

### 2.9 常驻引导控件清扫与弹层方案
