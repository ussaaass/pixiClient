# 十三张本地练习牌桌页面 SDD

版本：0.1（浏览器本地练习页校准）  
日期：2026-10-11  
范围：从 H5 大厅/子厅进入的十三张本地练习牌桌。此页用于验证 Pixi 客户端操作与规则展示；它不是匹配房间或联机牌桌，不收发金币、不持久化牌局。

## 1. 页面身份与运行边界

当前浏览器流程有两种入口：桌面大厅 → 十三张子厅 → 本地练习档 → 牌桌；手机大厅 → 卡内练习档 → 牌桌。牌桌由 `@gameing/shisanshui-client` 动态导入和挂载，H5 页面负责进入加载、失败重试及按入口返回；游戏画布负责随机发牌、理牌、演示对手、揭牌和纯本地计分。

本地练习的规则来源是 `@gameing/shisanshui-rules` 中的演示 `CLASSIC_V1_SCORING`。练习档位名称与下注数字仅作界面演示，不代表服务端配置或资产。退出或重新发牌不会产生可恢复的在线牌局。匹配队列、房间、服务器倒计时、断线恢复、自动托管和钱包结算属于未来联机页面，不能复用本地状态假装已完成。

## 2. 练习主流程

```text
大厅/子厅选档
  → H5 显示真实的模块导入与 Pixi 初始化阶段
  → 随机发给练习者 13 张牌，同时为 3 位演示对手生成合法摆法
  → 选择手牌，再点头/中/底墩放置；点已摆牌可取回
  → 可请求自动摆牌建议，也可重新发牌
  → 摆满 3/5/5 后开牌；倒道时清楚提示该局将按练习规则处理
  → 显示四家完整 13 张牌、各墩与练习得分
  → 再来一局或退出，并返回原来的大厅入口
```

### 2.1 进行中布局

```text
┌────────────────────── Pixi 练习牌桌 ──────────────────────┐
│ 十三张 · 新手厅              虚拟练习 / 不扣金币 [退出练习] │
│ 演示对手1 已摆好   演示对手2 已摆好   演示对手3 已摆好     │
│                                                            │
│ 头墩 3 张       [目标槽位]                                 │
│ 中墩 5 张       [目标槽位]                                 │
│ 底墩 5 张       [目标槽位]                                 │
│                                                            │
│ 手牌 13 张      [13 张可选择/点击放置]                     │
│ 状态说明       [自动摆牌] [重新发牌] [开牌比一比]           │
└────────────────────────────────────────────────────────────┘
```

三墩始终按玩家视角从远到近排列为头墩、中墩、底墩；底墩应最靠近自己的手牌。点牌后再点目标墩是主输入方式，已摆牌点选可取回。选中态、当前已放数量、每墩识别出的牌型和相公风险均需清晰可辨。已有牌面也属于当前牌墩的点击区域：有选中手牌时点击牌墩任意位置（包括已放入的牌）执行放置；未选牌时点击已放入的牌才取回。牌墩已满或尚未选牌时，必须在状态提示中说明原因并给出下一步操作，不能静默拒绝。自动摆牌是可继续调整的建议；重新发牌前不做资金或确认副作用。

### 2.2 开牌结果布局

```text
┌────────────────────── 本局摊牌 ───────────────────────────┐
│                     头墩        中墩        底墩            │
│ 你 · +N 水         [3张牌]     [5张牌]     [5张牌]         │
│ 演示对手1 · +N 水  [3张牌]     [5张牌]     [5张牌]         │
│ 演示对手2 · -N 水  [3张牌]     [5张牌]     [5张牌]         │
│ 演示对手3 · +N 水  [3张牌]     [5张牌]     [5张牌]         │
│ 相对你的墩结果      胜/负/平    胜/负/平    胜/负/平       │
│              [再来一局]       [退出练习]                   │
└────────────────────────────────────────────────────────────┘
```

桌面开牌页在同一屏显示四位玩家完整牌面，牌面按头/中/底分组且组界明显；对手行应同时显示相对玩家自己的逐墩胜负与总水数。手机布局见第 6 节，以玩家切换方式完整查看每家牌面。练习结果标注“虚拟水数”，不得显示为金币或真实结算。

## 3. 页面状态与操作

| 状态 | 内容和可操作项 | 离开/错误结果 |
| --- | --- | --- |
| 加载中 | H5 展示导入、初始化、准备牌局阶段；12 秒后可返回 | 失败可重试或按来源页返回 |
| 摆牌中 | 自己的 13 张牌、三墩槽位、牌型/数量/倒道提示、演示对手已摆好 | 退出回来源页；不保留牌局 |
| 牌组未摆满 | 允许继续选择/移回牌，禁止开牌 | 保留当前布局 |
| 完整合法牌组 | 可开牌，仍可调整或重新发牌 | 开牌后进入本局结果 |
| 完整但倒道 | 明确说明相公后果，要求玩家确认仍要按相公结果开牌 | 取消确认回到理牌 |
| 摊牌结果 | 四家完整牌面、逐墩结果、各家总水数；可再来或退出 | 再来随机发新局；退出返回原入口 |
| 画布/初始化错误 | H5 错误状态，不暴露堆栈 | 重试同档或返回来源页 |

## 4. 实现约束

- 当前练习采用“点选手牌 → 点墩位”交互；拖拽可作为后续 UX 增强，不把线框中的目标能力误记为现状。
- 所有牌、对手摆法、比较和水数仅存在于当前客户端内存。刷新/退出会丢失，结果不进入服务端、钱包、战绩或数据库。
- 练习对手在摆牌阶段只显示已准备状态，不泄漏其 13 张牌；只有玩家开牌后才绘制完整对手牌。
- Canvas 需覆盖容器尺寸；桌面以横向牌桌为主，窄屏必须保证手牌和动作区可触达，不以画布缩放掩盖文本/卡牌不可读问题。
- 规则比较顺序仍由纯规则包负责；Pixi 仅消费结算结果并表现牌面/胜负，不自行重新计算分数。
- 操作音效由游戏客户端的 `PracticeAudioPort` 表现层适配器使用 Web Audio 合成：选牌、放牌/取牌、自动摆牌、重发、无效操作与结算胜负各有轻电子音；`LocalGameOptions.soundEnabled` 由共享客户端偏好投影提供。音效不参与领域状态或结算，关闭偏好时不创建 AudioContext，退出牌桌时关闭上下文；正式素材音效包就绪后替换表现适配器，不改变用例/规则。
- 设置 UI 仅把 `soundEnabled` 注入游戏模块的渲染选项；Pixi 模块不读取 LocalStorage、Vue 或平台设置状态。声音音序表由牌桌客户端自己解释，未来替换为压缩音效文件时仍保持 `PracticeAudioPort` 事件边界。
- Canvas 之外提供可展开的原生 HTML 键盘/读屏操作替代层：语义化手牌按钮、三道放牌/取回按钮、自动摆牌/重发/开牌/退出及逐家逐墩结果；原生按钮可用 Tab、Enter/空格操作，`aria-pressed` 表达选牌，稳定的 `role=status`/`aria-live` 播报操作结果。牌局状态更新时保留焦点；放牌后焦点转到该牌的取回按钮，取回后转回对应手牌。
- 辅助入口为 44×44 px，并动态布置在 Pixi“退出练习”按钮左侧 8 px，不覆盖主操作；打开后面板本身滚动，关闭入口仍保留。
- Pixi Canvas 本身仍不能向屏幕阅读器暴露画面结构；等价 DOM 控件提供玩法操作和文字结果，不宣称 Canvas 变得语义化。Safari/VoiceOver、TalkBack 实机朗读与焦点次序仍需人工验收。

## 5. 当前实现校准与 Checklist

- ✅ H5 按桌面子厅/手机卡内选档的来源分别返回；Pixi 动态导入、初始化失败重试、慢加载返回均已接入。
- ✅ 本地发牌、13 张手牌、点选放入/取回、自动摆牌建议、重新发牌、合法性与规则结算由规则包驱动。
- ✅ 开牌后绘制你与三位演示对手的全部 13 张牌，结果保留在本地内存；支持新局。
- ✅ 理牌顺序为头墩、中墩、底墩；揭牌区按三墩分组，并为每个演示对手显示相对自己的逐墩胜/负/平。
- ✅ 倒道时需再次点击确认相公开牌，并提示该局将按本地练习规则判负。
- ✅ 练习牌桌按 `soundEnabled` 播放轻量电子操作/结算音；关闭设置后静音，离桌释放 AudioContext。
- ✅ H5 Vitest 验证语义化操作包含手牌选择、目标墩选择、ARIA 选中态、实时状态文本、焦点保持/放牌后焦点迁移、完整结果文本与退出回调；Chrome 真实运行验证 390×844 可展开操作并选牌播报，320×568 面板滚动可用。
- ✅ Headless Chrome 检查 1280×800、1280×650、844×390、430×932、390×844、360×800、320×568：各视口页面 `scrollWidth/clientWidth`、`scrollHeight/clientHeight` 均等于视口宽高，Pixi 画布完整覆盖视口；辅助入口 44×44 且与退出按钮不重叠。320×568 展开面板 300×386，面板内容 `scrollHeight/clientHeight` 为 847/384，根文档仍为 320/320、568/568。
- ⬜ iOS Safari/VoiceOver 与 Android Chrome/TalkBack 真机朗读、焦点浏览、系统字体放大、地址栏/安全区及横竖屏旋转验收；当前浏览器模拟不替代真机。
- ⬜ 减少动态效果设置的牌桌反馈验收；练习桌目前没有持续装饰动效，待牌桌特效接入后验收开关。
- ⬜ 联机牌桌与房间流程：等待后端权威状态、Socket.IO ACK/恢复及结算 DTO 后另行施工；本地练习不得标为匹配/房间闭环。

## 6. 手机竖屏牌桌校准（2026-10-16）

手机竖屏采用独立 Pixi 排版，宽度小于 650 px 且高度不小于宽度时启用；桌面和横屏继续使用原牌桌。H5 外壳使用十三张子厅背景图，并叠加深色渐变保障牌面反差；Canvas 透明绘制，避免不透明底色盖住背景。外壳预留系统安全区。颜色以墨绿桌布、象牙白/灰白文字和清晰暖金边框为主；文字仅使用纯填色，不添加文字描边或边框。常态牌槽使用可辨识的金色描边，选中后进一步提亮，牌墩已满时也用金色区分状态；避免绿色边框与桌布混在一起，也避免重复叠加多层高亮边框。

进行中页面从上至下为：游戏标题/离开、三名对手的紧凑状态条、头/中/底三道纵向牌槽、自己的 13 张手牌（7+6 两行）、状态提示和底部四按钮。牌槽整体均可作为目标点击区，选牌后以柔和金色描边提示可放置；牌槽已满或未选牌时通过状态提示反馈具体原因和下一步。已有牌面在选中手牌时点击执行放入，在没有选中手牌时点击取回。底部操作保持大触控目标。正常竖屏下规则操作仍为“点手牌、点目标墩”，不要求拖拽。自动游戏弹层选择局数后启动，运行中显示已完成局数和停止入口。

“自动游戏”弹窗提供 10、50、100 局和无限局选项；选定后从当前手牌开始自动理牌、摊牌，结果展示 1.5 秒后再开始下一局。进行中的结果页提供“停止自动游戏”，停止不会撤销已经完成的牌局；有限局数达到上限后停在最后一局结果。局数是本地练习预览值，不代表生产 `game_config`。此模拟不消耗金币或写入数据库，也不替代线上自动模式、服务端机器人或掉线托管。“自动摆牌”仍只给出可继续调整的摆牌建议。

手机摊牌页使用四个玩家切换按钮，选中玩家后纵向展示其头/中/底三道完整牌面、逐墩牌型和相对结果。此处不再把四家的 52 张牌同时压缩到一屏；每位玩家的完整结果仍可逐一查看，桌面原有四家同时摊牌保持不变。
