# 玩家大厅 Mobile 布局与视觉 SDD

版本：1.0（首版施工）  
范围：玩家 H5 游戏大厅在手机竖屏中的信息架构、固定导航、首屏游戏选择、背景裁切和触控适配，并记录桌面十三张子厅的视口尺寸与难度横向滚动约束。十三张 Pixi 牌桌的操作布局另见游戏客户端 SDD；桌面大厅仍使用横向大屏布局。

## 1. 问题与目标

现有页面把品牌、介绍、游戏卡片、大厅功能入口依次放进可滚动页面。手机上游戏卡片可能在首屏以下，钱包、战绩、邀请、社区、客服和设置也随内容滚走。用户必须长距离下滑才能找到主功能。桌面大厅的 3:2 背景又被铺满到窄屏，主体裁切后仅剩很小一块，背景和页面内容比例失衡。

移动版应让用户打开页面后立即看见游戏入口；常用功能始终可达；背景专门按手机构图生成；内容可在小屏和安全区内阅读、点击。不得要求用户旋转手机，也不得为展示背景而牺牲文字与按钮对比度。

## 2. 信息架构

手机大厅分为三层：

1. **顶部状态栏**：品牌标志与连接状态。品牌不承担导航以外的新功能，状态文案在窄屏截断但保留状态点和可访问名称。
2. **可滚动主舞台**：简短欢迎标题和横向吸附游戏卡片。手机十三张卡片内部纵向排布封面、规则摘要和难度选项；选难度后直接进入练习，不再经过独立子厅页。后续游戏卡片露出边缘，提示可横滑。
3. **固定底部快捷栏**：游戏、钱包、社区、客服、我的五个入口。包含 `safe-area-inset-bottom`，固定在视觉视口底部，滚动主内容不推动它。

战绩、邀请/代理、消息和设置由“我的”面板提供二级快捷入口；钱包、社区、客服可从固定导航一步直达。桌面端仍显示原顶部操作区和功能按钮网格，不显示移动底栏。

在 320–430 CSS px 宽度下，游戏卡片采用横向滚动与 `scroll-snap`。卡片首行将封面 Logo 与标题区并列，以缩短卡片纵向高度；标题同行提供圆形问号+“规则”按钮。其下单独放置游戏简介，再纵向排布难度。规则说明通过易发现的弹出层触发入口打开，不在卡片中堆叠长篇规则。浏览器高度较短时，大厅根容器锁定视口高度并隐藏根滚动，纵向滚动只发生在大厅壳内；顶部品牌和底部导航仍可达。难度与规则点击热区不低于 44 CSS px。

各难度至少展示**最低下注、当前倍率、最高倍率**。当前本地练习显示虚拟练习分演示值（新手 10 / 1× / 5×，进阶 50 / 1× / 10×，策略 100 / 1× / 20×），紧邻标注“演示配置，不扣金币”。上线后必须读取共享 `GameTierDto`，不得把这些示例值用作线上参数。

## 4. 视觉与背景规范

- 桌面继续使用 `lobby-background.webp` 横版图。手机使用独立 9:16 左右竖版图 `lobby-background-mobile.webp`，不得用桌面背景缩小填满。
- 竖版背景延续圆润 3D 卡通质感、深青绿/祖母绿、暖象牙白和克制金边。两侧建筑只做边缘框景；上方标题区、中部游戏卡片区和底部导航区保持低细节，避免主体和文字冲突。
- 移动背景使用 `object-fit: cover; object-position: center`；其构图按窄屏预留，不靠拉伸、不依赖运行时位置抖动修正。页面切换背景维持固定视口图层和淡入，不与主内容滚动绑定。
- 图片 WebP；移动图的运行时文件约 71 KB。生成源 PNG 保留在美术工作区供后续重导出，不由客户端加载。
- 背景上方使用深色渐层保障文字对比；卡片使用不透明度足够的面板底色。装饰不接受点击，也不遮挡滚动手势。
- 卡片封面与标题行在卡片边框内缩进至少 12 px；封面自身边框、圆角和底色不得贴合或覆盖父卡片上边框。
- 触屏按钮关闭浏览器默认蓝色 tap-highlight 闪烁；键盘 `:focus-visible` 仍保留高对比度焦点描边。

## 5. 交互细节

- 手机十三张卡片首行并列显示封面 Logo 与标题/规则入口；标题下方是独立游戏简介，再往下是难度列表。选难度直接进入 Pixi 本地练习，不再经过子厅页。桌面仍为大厅→子厅流程。
- 手机规则由问号图标+“规则”按钮打开底部弹层；桌面规则留在子厅。规则覆盖牌数、3/5/5 分墩、倒道、牌型大小和逐墩计分；特殊牌/打枪奖励注明按本厅配置。
- 桌面子厅与移动游戏卡均显示最低下注、当前倍率、最高倍率；本地值明确标记为虚拟练习演示配置。
- 不显示独立“重新连接”按钮。离线状态指示器变为可点击重连控件；在线/检查中状态禁用点击。
- 游戏卡片横滑只作用于卡片轨道，页面仍可纵向滚动；触屏支持惯性，键盘/辅助技术仍可顺序聚焦每张卡片。
- 固定导航每个入口有图标、文字与至少 44×44 CSS px 点击热区；激活项有颜色和背景双重提示。当前大厅游戏入口使用 `aria-current="page"`。
- 点“我的”打开底部抽屉式弹窗，其中提供个人资料、战绩、邀请与代理、消息、设置；抽屉高度受动态视口约束，滚动发生在抽屉内部，并适配底部安全区。
- 钱包和邀请面板的扩展说明只通过标题旁“？”打开蒙层弹层；不在抽屉内容中常驻重复说明卡。涉及真实金额、资格、隐私和安全的确认信息仍须贴近实际操作展示。
- 弹窗打开时大厅主页面设为 `inert`，从焦点和无障碍树中隔离；body 固定并保存滚动位置，关闭后恢复滚动位置与焦点。Esc 关闭和 Tab 焦点圈已由大厅弹层交互实现；真机读屏及 reduced-motion 仍需验收。
- 子厅保留既有横向难度卡片体验。移动底栏当前只属于大厅，进入十三张子厅或牌桌时隐藏，避免与游戏内操作栏争用空间。
- `100svh` 用于稳定首屏最小高度；`100dvh` 用于弹窗等跟随动态浏览器工具栏的最大高度。顶部/底部 padding 使用安全区环境变量并提供普通 padding 回退。

### 5.1 桌面子厅的视口与难度滚动

- 桌面子厅高度锁定为 `100dvh`（回退 `100vh`），内部纵向采用 flex 布局；页壳隐藏溢出，桌面页面本身不得因子厅内容出现纵向滚动条。
- 难度卡片轨道占用子厅可用剩余高度，使用 `overflow-x:auto`、`overflow-y:hidden`。卡片按最多同时展示三张的宽度定尺寸，第四张及之后通过横向滚动访问；滚动条需保持可见，轨道可通过键盘聚焦并以方向键滚动。
- 子厅标题、规则、档位提示和页脚压缩在视口内；矮桌面窗口通过 `max-height` 断点收紧间距。若规则内容未来增长，需重新验收，不能让页壳悄悄恢复纵向溢出。
- `.mobile-dock` 只在 `max-width:720px` 显示，桌面默认显式隐藏；桌面大厅仍使用顶部操作区和功能按钮网格。
- 页面修改后按项目纪律检查实际视口宽高。桌面至少覆盖 1280×800 和较矮窗口 1280×650；移动至少覆盖 390×844 与窄屏 320×568。比较 `scrollWidth/clientWidth`、`scrollHeight/clientHeight`，允许难度轨道自身横向溢出，禁止桌面子厅根页面非预期溢出。

### 5.2 桌面大厅游戏卡带

- 桌面游戏目录占据内容区整行，卡片按横向卡带排列，可使用触控板或聚焦后的方向键左右浏览，滚动吸附以卡片为单位；横向滚动条隐藏，不额外占据卡带下方空间。
- 初始顺序为跳高高、夺宝奇侠、麻将胡了、十三张、麻将胡了 2、捕鱼、赏金女王、3快。跳高高与夺宝奇侠都是 Slot 多线+积分游戏。进入桌面大厅后自动将第 4 张十三张卡定位在轨道中央；它是当前可玩的游戏，其余规划中模块显示“敬请期待”并禁用进入按钮。浏览器宽度跨过 720px 断点时，桌面重新居中十三张，移动端回到卡带起点。
- 桌面单卡宽度使用约 230–270px、高约 220px，而不是两张卡平分整行；卡片内部明确展示游戏标题、简介和进入状态，常见桌面宽度同时露出多张卡及相邻卡片边缘，提示卡带可横向浏览。只有十三张卡保留可玩的规则与难度内容。
- 每款游戏的图标、静态背景都必须在 Mobile 卡片中使用对应主题资源：十三张保留图标+标题同行、简介、规则入口和难度列表；其他七款使用图标列+标题/简介/开放状态。共用 `assetKey` 加载，不复制一套 mobile 图片，也不把方形图标拉伸为横图。宽幅背景用 `cover` 裁切并以 CSS 控制焦点位置。
- 手机卡片的焦点卡可沿用同一动态 AVIF，但同一时刻最多一张播放；滚动时显示静态 poster，停稳并确认当前焦点后再切到动画。若省流量、低带宽、减少动态效果或页面进入后台，维持静态 poster。PC 细节见[PC 大厅游戏卡片与动效背景 SDD](./PC大厅游戏卡片与动效背景SDD.md)。
- 桌面大厅功能工具栏通过弹性上边距靠近视口底部，底部提示文字与工具栏之间保持紧凑间距，避免工具栏下方留下大片空白。
- 桌面功能工具栏使用等宽网格：宽度至少 1100px 时六个按钮等宽单行显示，较窄桌面使用三列两行；图标与长短不一的文字在按钮内居中。移动端隐藏该按钮组，使用固定底栏。
- 移动端仍将十三张排在首位，保持当前单卡宽度、简介、规则入口及纵向难度选择；游戏目录仍可横向滑动。
- Mobile 用户在十三张游戏卡内选择难度后直接进入牌桌；退出牌桌回到大厅中的十三张卡，不经过桌面子厅。桌面流程仍是大厅 → 子厅选档 → 牌桌 → 原子厅。

## 6. 实现边界

- 当前 Vue 页面使用一个公共 DOM，由 CSS 响应式切换桌面和手机排布；导航命令仍调用现有 `openLobbyPanel`，不复制业务页面状态。
- 移动底栏只承载 H5 大厅功能，不进入 Pixi Canvas。设置偏好属于本地客户端状态，由共享 `ClientPreferenceDto`、application 和 LocalStorage adapter 管理；钱包及身份敏感操作仍由服务端会话与账本事实决定。
- 不为此引入 UI 库、路由器或新的响应式框架。后续服务端 capability 接通后，由共享 DTO 决定社区等入口可见性。
