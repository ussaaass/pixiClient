# 大厅与后台 UI 走查与优化建议

本文记录 2026-10-21 对玩家大厅（`apps/web`）与管理后台（`apps/admin`）在真实浏览器中的走查结果与优化建议。所有结论均来自 Docker 编排起的真实服务（server `10300` / web `10373` / admin `10374`）与真实 Chromium 渲染，附几何测量值；未做视觉改版，未修改任何页面代码。

## 走查环境

- 运行方式：`docker compose --profile full up -d --wait`，MySQL / Redis / Koa 服务端 / 大厅 / 后台容器全部 healthy。
- 浏览器：agent-browser 驱动真实 Chromium（非 happy-dom 模拟），桌面视口 1440×900，移动视口 390×844。
- 覆盖页面：大厅 `/`、十三张子厅 `/games/shisanshui`、登录与账号恢复 `/entry`、钱包 `/wallet`、社区 `/social/forum`、消息 `/messages`、本地练习牌桌（大厅 → 十三张 → 新手厅）、后台 `/admin/overview`、`/admin/users`、`/admin/payments/orders`。
- 几何口径：记录 `innerWidth/innerHeight`、`documentElement.scrollWidth/clientWidth`、`scrollHeight/clientHeight`，并对设计内横向滚动容器单独验收。

## 逐项问题与建议

### P0-1 桌面大厅卡片带首尾被裁切

- 现象：1440×900 下大厅一排 8 张卡片，轨道 `clientWidth` 1425、`scrollWidth` 2590，初始 `scrollLeft` 为 184。首张「跳高高」左边界为 `-127.25`（被裁 127px），末张「3快」右边界 1793（被裁 368px）。轨道 `overflow-x: auto` + `scroll-snap-type: x mandatory`，但没有任何左右箭头、分页点或渐隐提示，首张游戏在默认视口里被切掉一半。
- 影响：新玩家第一屏看不到列表第一项，且没有任何可发现的滚动入口；`docs/00_problem/人机工程学问题.md` 已记录 PC 全宽卡片方向，但当前实现停在「能横滑」而不是「能完整浏览」。
- 建议：
  1. 桌面端改为 5 列网格 + 分类分页（或 4 列 × 2 行），保证 8 款游戏一屏内完整可见，不依赖横向滚动。
  2. 若保留横滑，必须提供左右箭头按钮、渐隐遮罩与当前位置指示，且首屏 `scrollLeft` 归零、末张完整对齐。
  3. 首屏渲染前不要让轨道获得焦点（当前 `.game-row` 在加载后即持有焦点，是 `scrollLeft=184` 的直接来源）。

### P0-2 移动端引导层越界并压住正文

- 现象：390×844 子厅页首次引导 `.subhall-guide` 实测 `left=188`、`right=531`，面板宽 343px，而视口 `clientWidth` 仅 375 —— 面板右侧有 156px 落在视口之外被裁掉。引导层同时与两段正文矩形相交：「按项目十三张规则说明；当前只提供本地…」（31,584)-(344,628)）和「难度卡可横向浏览，卡片会显示最低下注…」（205,560)-(514,596)）。
- 附带问题：引导遮罩 `.hall-guide-scrim` 为 `rgba(2,11,8,.74)` 全屏固定层，首屏进入大厅与子厅时整页被压暗 74%，主视觉（标题、背景图）完全被盖住。
- 建议：引导层改为视口内约束（`left/right` 用 16px 内边距、宽度 `min(343px, 100vw - 32px)`）；引导锚点改为指向被讲解的元素而不是浮在正文上；遮罩改为弱化（例如 `rgba(2,11,8,.45)`）或只在桌面端启用；首次进入的大厅/子厅不再自动弹引导，改为一次性顶部轻提示条。

### P1-1 卡片内联难度列表重复渲染

- 现象：大厅 8 张卡片内共含 40 个按钮，其中桌面端可见仅 8 个，其余 32 个（每游戏 3 个难度 + 1 个规则入口）为隐藏的重复难度列表。
- 影响：无谓的 DOM 与无障碍树体积；读屏会朗读不可见控件；后续每接入一款游戏，隐藏 DOM 线性膨胀。
- 建议：卡片只保留「查看游戏厅」入口，难度列表仅在进入子厅后渲染（当前子厅已能独立渲染难度卡，无需在卡片内预置）。

### P1-2 移动端卡片视觉顺序错位

- 现象：移动端可玩游戏「十三张」使用 `order: -1` 被提到轨道首位，其余卡片 `order: 0` 保持原序，导致视觉顺序变为 十三张 → 跳高高 → 夺宝奇侠 → 麻将胡了 → 麻将胡了 2 → 捕鱼 → 赏金女王 → 3快，三款「即将开放」游戏被夹在可玩游戏与后续可玩游戏之间。
- 影响：分类分组语义被打乱；玩家横滑时难以建立稳定预期。
- 建议：不用 CSS `order` 改序，直接在数据层按「可玩优先、其次未开放、最后同系列」重排数组，使 DOM 顺序与视觉顺序一致；排序结果写进同一份 `LOBBY_GAME_REFERENCE` 派生逻辑，避免大厅、子厅两处各自排序。

### P1-3 字号体系整体偏小

- 现象：`apps/web/src/style.css` 共 465 处 `font-size` 声明，其中 305 处小于 12px（8px × 48、9px × 100、10px × 99、11px × 56）。实测大厅卡片标签 9px、卡片描述 10–11px、卡片按钮 10px、顶部导航 10px；子厅难度卡指标 8–9px。
- 影响：中文小字号在 1x 屏与移动端可读性差，低于 12px 属于明确的可用性缺陷；桌面端本可用更大字号换取更清晰的信息层级。
- 建议：定义 5 级字号刻度（正文 14 / 辅助 12.5 / 标签 11.5 / 数字指标 12 / 标题 18+），把 8–9px 只留给角标与装饰；桌面端正文与卡片描述分别提到 13px 与 12px，移动端正文 14px；用 CSS 变量统一刻度，避免 1535 行样式表里散落 465 处硬编码字号。

### P1-4 社区与消息正文缺少承载层

- 现象：社区论坛（桌面）与消息页的帖子行、活动行没有半透明卡片底，只有细边框，文字直接压在赌场照片背景上；同页的钱包面板却有 `rgba(4,17,14,.58) + blur(4px)` 承载层，风格不统一。
- 影响：正文在照片明暗变化处忽隐忽现，是本次走查中桌面端最影响阅读的一处。
- 建议：为帖子行、活动行、消息行统一引入与钱包同规格的半透明承载层（背景 + blur + 1px 金色描边），并把该规则抽成可复用类，避免每处各写一份 `backdrop-filter`。

### P1-5 后台下拉组件触发 Vue 性能告警

- 现象：`/admin/payments/orders` 控制台稳定输出 `[warning] Non-function value encountered for default slot. Prefer function slots for better performance. null at <ElOption>`，栈指向 `AdminSelectOption.vue`。该组件用 `h(ElOption, props, slots.default?.())` 把已渲染的 VNode 数组当作默认插槽传入，并因此把子节点渲染两次。
- 影响：所有使用该组件的后台下拉框都会重复渲染子节点并产生告警噪音，后台页越多越明显。
- 建议：改为函数插槽 `h(ElOption, props, { default: () => slots.default?.() })`，并把 `label` 的文本提取与渲染合并为一次调用。

### P2-1 练习牌桌观感与文案不一致

- 现象：
  - 桌面（1440×900）：标题区与手牌区之间约 380–490px 为纯空白，页面 `scrollHeight` 900 恰好等于视口高度，内容却只占上下两块；三个牌堆区是空心描边框。
  - 移动（390×844）：背景换成绿呢质感，与桌面端的纯深绿不一致；手牌为 7 + 6 两行，同样在中段留下约 200px 空白。
  - 按钮文案两端不同：桌面「开牌比一比」，移动「开牌比牌」；副标题桌面「本地练习 · 随时结束 · 不涉及金币或真实结算」，移动「本地练习 · 不涉及金币」。
  - 牌面为文字字形（`Q♠ A♥ 10♠`）加白色圆角块，而 `tools/asset-generation` 已生成整套 384×512 WebP 牌面素材却未在此使用。
  - 对手槽位直接暴露内部状态文案「已翻牌 · 13 张」。
- 建议：统一两端牌桌骨架与文案（中文案收敛到一处常量）；用现有 AI 牌面素材替换文字牌；牌桌背景与大厅背景统一到同一套视觉语言；把「已翻牌」等内部状态改为玩家语言；对手区补充头像/投入/倒计时占位，为联机预留但不在本地练习伪造。

### P2-2 后台与前台风格割裂、控件混用

- 现象：后台为浅色主题（`#f7f8fa` 系）而前台为深绿金主题；后台「充值订单」的筛选区使用原生 `<select>`（系统外观），同页其他位置使用 Element Plus 组件；侧边栏 24 项在 900px 高度下底部「Tron 充值监控」被裁切；空状态「暂无充值订单」只给了一行 11px 说明。
- 建议：后台保留独立浅色主题是可接受选择，但需统一为 Element Plus 控件（下拉、日期、空状态、表格），补齐侧边栏分组折叠或滚动提示，空状态补充「可执行的下一步」引导。

### P2-3 主导航存在两套模型

- 现象：大厅桌面使用右上角文字导航（充值/钱包、战绩、邀请/代理、消息、设置），二级页使用右下角浮动胶囊导航（游戏、钱包、社区、消息、我的）。两者项目不一致：「战绩」「邀请/代理」只在大厅存在，「社区」只在胶囊导航存在。
- 建议：统一为一套主导航模型（大厅与二级页共用同一导航数据源），PC 端把浮动胶囊改为固定顶部导航或保留胶囊但补齐同一组入口。

### P2-4 登录页暴露开发态入口

- 现象：`/entry` 在「未登录」标签下同时显示「检查本机凭证」与「生成测试证书」两个按钮，后者是开发环境专用动作。
- 建议：以 `import.meta.env.DEV` 隔离开发态按钮，或在生产构建中隐藏「生成测试证书」。

## 建议排期

1. **第一批（体验阻断）**：P0-1 桌面大厅卡片布局、P0-2 引导层越界与遮挡。两者都是首屏可见缺陷，改动集中在 `apps/web/src/style.css` 与大厅卡片渲染顺序。
2. **第二批（可读性与性能）**：P1-1 卡片内联难度列表下线、P1-3 字号刻度统一、P1-4 内容承载层、P1-5 后台插槽修正、P1-2 移动端排序改为数据层排序。
3. **第三批（一致性打磨）**：P2-1 牌桌骨架与文案统一、P2-2 后台控件统一、P2-3 导航模型统一、P2-4 开发态入口隔离。

第二批涉及 1535 行样式表的字号与承载层调整，建议先在 `docs/06_ux/` 增补字号刻度与承载层规范，再逐页替换，避免边改边扩散。

## 未闭环事项

- 本次只做走查与建议，未改任何页面代码，因此未触发新的视口几何复验；上述几何数据为改动前基线。
- 牌桌未做多分辨率适配矩阵（仅 1440×900 与 390×844 两档），也未覆盖平板与超宽屏。
- 后台未做全部路由的逐页走查，仅覆盖总览、用户、充值订单三页。
- 未做完整可访问性审计（键盘全流程、读屏朗读顺序、对比度全量检测），仅对可见文本字号与引导层遮挡做了抽样。
- 社区与消息页正文对比度未做像素级测量（背景为照片，`backgroundColor` 链路无法代表实际对比度），P1-4 的结论基于渲染观感与承载层缺失的客观事实。
