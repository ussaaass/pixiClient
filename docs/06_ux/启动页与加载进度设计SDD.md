# 启动页与加载进度设计 SDD

阶段：前端首屏施工规范。目标是低速 4G、首次访问或资源加载较慢时不出现白屏；在 Vue 与业务 JS 尚未启动前也能看到品牌化加载界面，并持续说明当前进度与状态。

## 1. 现状与边界

当前 `apps/web/index.html` 已包含不依赖 Vue 的品牌化静态启动壳、约数百分比、持续扫光、15 秒慢载说明、“继续等待”和“重新加载”；`main.ts` 在 Vue mount、首帧和大厅 ready 时校准进度并移除启动壳。启动估算使用近期同源速率样本或浏览器网络提示，不声称是实时下载字节百分比。健康检查只更新大厅在线状态，不阻塞本地大厅和练习。

2026-10-12 当前生产构建记录：入口 `index-*.js` 148.58 KB（gzip 50.56 KB），入口 CSS 29.55 KB（gzip 7.17 KB）；动态导入的 Pixi/十三张 chunk `src-*.js` 296.59 KB（gzip 89.43 KB），没有进入入口 bundle。该记录来自最近一次 Web 构建，资源变更后必须重测；Vite 开发模式请求图不能代表生产冷启动。

本 SDD 覆盖：HTML 静态启动壳、启动状态与进度、首屏降级、错误恢复、低速网络验收。Headless Chrome 已验证入口模块延迟/失败状态、生产预览冷缓存限速状态及桌面/手机首屏几何；真实手机、实际大陆/海外 CDN 路径、浏览器间差异和真实移动网络仍未验收。开发服务拦截仅验证状态机，不作为性能结论；本机 Docker production preview 的限速结果只作为可复现基线，不承诺真实用户带宽表现。它不把服务端健康检查、后台预取、PixiJS 游戏加载纳入大厅启动完成条件。

## 2. 体验目标

- 从 HTML 首次绘制开始就显示有品牌、有层次的页面，不依赖 Vue、字体、WebP 或远程图片才能画出加载画面。
- 用户始终看见当前阶段、百分比、持续活动的视觉反馈；下载慢时不让进度条冻住，也不假装下载字节已被精确测量。
- 大厅壳先启动。健康检查、游戏封面、场景背景、PWA 注册和闲时预载不能挡住大厅交互。
- 入口 JS 失败、断网或等待过久时，显示可操作的重试状态和清晰文案；不能无限白屏或只留旋转图标。
- 动效克制、有节奏，支持 `prefers-reduced-motion`，不播放声音、不强制横屏。

## 3. 视觉方案

### 3.1 设计语言

沿用 Lottery Game / LG 的翡翠绿、暖象牙白、金色系统。加载画面使用纯 CSS 绘制的深绿径向光晕、细金色边框、柔和粒子/光带和一条明亮的进度轨道；不铺满屏幕的 AI 背景图，不堆叠金币、老虎机、卡牌人物或闪烁爆炸特效。已有透明 LG 徽记可作为渐进增强项；即便徽记资源尚未到达，也必须显示 CSS/文字版 `LG` 和 `LOTTERY GAME`。

### 3.4 动效

- 背景光晕以 8–12 秒缓慢呼吸，进度轨道使用低幅度金色扫光，主徽记只做轻微亮度呼吸；禁止持续缩放/弹跳和高频闪烁。
- 进度值变化使用 180–350 ms ease-out 过渡；加载期间扫光继续移动，即使百分比因等待关键阶段而暂时不变，仍能看出网络请求/启动任务在进行。
- 初始化完成后，静态启动壳淡出 180–260 ms；大厅首屏淡入，不缩放页面，不造成背景尺寸跳动。
- `prefers-reduced-motion: reduce` 时取消扫光/呼吸，只保留静态进度和明确状态文字。

## 4. 进度百分比语义

### 4.1 显示原则

启动页必须显示数字百分比。它代表**大厅启动任务完成度估算**，不命名为“已下载字节百分比”。百分比旁显示“约”，例如“约 42%”；阶段文字单独说明正在下载、挂载或渲染什么。页面不可把 `navigator.onLine`、服务健康检查结果或动画经过的时间写成已经下载完成的资源。

原生 `<script type="module">` 只给页面脚本 `load`/`error` 等完成事件；标准 Resource Timing 暴露的 `responseEnd` 和资源大小是在响应计时记录中使用的字段，不提供原生 module script 的实时下载进度。XHR/Fetch 流可以报告传输进度，但若用它预下载 ES module 再执行，须处理缓存复用、模块相对导入、动态 chunk 与重复下载问题。首版不因此自造第二套模块加载器。[HTML script 元素](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script)、[Resource Timing](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceResourceTiming)、[XHR 下载进度事件](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest_API/Using_XMLHttpRequest)

因此百分比采用**有界估算 + 真实阶段校准**：

1. HTML 静态壳首次绘制为 3%，阶段为“正在连接游戏大厅”。此时 JS 尚未执行，进度轨道继续动，文案说明正在准备启动资源。
2. 入口 JS 等待期间，根据可用信息估算进度：优先使用本 origin 最近 7 天成功启动 JS 的压缩体积/响应体时间样本，以 EWMA 平滑并乘 0.7 安全系数；无有效历史样本时，读取 `navigator.connection` 的 `downlink/effectiveType`，再乘 0.7 安全系数；不可用时采用保守默认速率。首版以 230 KiB 作为入口静态模块图的保守传输估计，构建接入 manifest 后用生产版本实际 P0 encoded bytes 替换。低置信阶段始终显示“约”。
3. 估算进度单调递增，在 JS 成功执行并发出 `app:mounted` 前最高不超过 72%；采用渐近曲线，慢网持续等待时不会在预计时间刚到后马上长时间顶格。不允许在估算用尽后到达 100%。模块 `load`/Vue 挂载事件到达后，将进度校准到 78%，阶段改为“正在布置大厅”。
4. 首个大厅 DOM 已提交且至少经过一帧绘制后进入 92%，阶段为“大厅即将就绪”。应用发出 `app:ready` 后转为 100%，显示“大厅已就绪”，再完成启动壳淡出。
5. 若某些启动里程碑提前完成，进度只能平滑向前，不回退；如果慢于估算，按实际等待延后，但 72% 上限与活动扫光避免显示虚假的完成状态。

百分比权重与上限集中在启动进度协调器的命名常量中，禁止组件里散落魔法数字。开发诊断记录阶段耗时、估算置信度、版本和缓存冷/热状态；不记录玩家资产、凭证或完整 URL query。首次冷启动估算较粗，指标上应区分预测值与由阶段事件确认的值。

### 4.2 启动关键资源

构建产物产生启动 manifest，明确入口 JS、其静态 imports/CSS 及传输编码大小；PixiJS、十三张规则 UI、高分辨率背景、客服面板和其他游戏均不列入大厅 P0。manifest 文件体积极小并随 HTML 构建版本化，资源 hash 必须对应实际构建文件。

HTML 内联 CSS 负责首屏最小视觉；可内嵌一个纯文字 LG 徽记兜底。AI 生成徽记在 DOM ready 后按 P0/小尺寸渐进加载，失败仍保留文字标。大厅背景、游戏封面通过占位颜色先画布局，再异步下载/解码和淡入；图片不作为 100% 大厅可交互的前置条件。

## 5. 页面启动状态机

```text
STATIC_SHELL
  ├─ app:mounted → MOUNTING_HALL
  ├─ script error / bootstrap timeout → STARTUP_ERROR
  └─ offline signal → MOUNTING_HALL（本地大厅仍可进入）

MOUNTING_HALL
  ├─ first frame painted → HALL_READY → 100% → FADE_OUT
  ├─ API unavailable → HALL_READY_OFFLINE（不阻挡本地练习）
  └─ fatal render error → STARTUP_ERROR

STARTUP_ERROR
  ├─ 继续等待 → 保持 STARTUP_ERROR 并继续监听启动结果
  └─ 重试 → 页面安全重载并回到 STATIC_SHELL
```

服务健康检查只更新 Vue 大厅内的在线状态，不阻断 `HALL_READY`。静态壳处理 module script `error`，显示“启动资源未能完整加载”；达到 15 秒无 mount 信号后提供“继续等待”和“重试加载”，不得无解释地自动刷新。重复失败时显示短诊断码，便于客服定位。在线探测和 JS 失败按不同文案分类。

## 7. 实施边界

- `index.html` 提供静态壳和最小内联关键 CSS；无外链字体、外部 CDN 样式、AI 全屏图或 JS 初始化依赖。
- `main.ts` 在 Vue 成功挂载后发送启动阶段事件；大厅根组件在首帧提交后报告 ready。阶段事件使用窄小的 `BootProgressPort`，不能让 App 直接操作静态壳的任意 DOM。
- 新增轻量 `boot-screen` CSS/状态控制；按现有 Vue/H5 分层实施，不引入额外 loader 库、Worker 或新的领域服务。
- 错误按钮通过静态小脚本更新壳或安全重载；不使用 `innerHTML` 拼接网络错误内容。
- PWA/Service Worker 后续安装可提升暖启动命中，但首访不假定 SW 已经控制页面；冷启动仍须通过静态壳正常反馈。
- 游戏内 Pixi 加载继续使用独立游戏加载 overlay，不复用大厅启动进度状态，避免阶段和进度口径混淆。

## 8. 验收 Checklist

- ✅ 禁用 JavaScript 时，首屏仍显示完整静态品牌加载页和可读说明，不呈现白屏（源码结构确认；不同浏览器视觉验收待做）。
- ✅ Headless Chrome 延迟 `src/main.ts` 请求：手机 390×844 静态壳先绘制，根文档 390/390、844/844，入口未完成时显示约 19%；桌面 1280×657 根文档 1280/1280、657/657，延迟 15 秒显示 71% 和继续等待/重新加载，强制入口失败后保持错误状态与重试，不显示大厅已就绪。
- ✅ 本机 Docker production preview 首次冷缓存模拟 4G（Chrome Network emulation：下载 196,608 B/s、延迟设为 160 ms，Navigator 上报 downlink 1.65 Mbps、RTT 100 ms）；390×844 下静态壳采样 348 ms 已可见、FCP 444 ms、DOM ready 676 ms、大厅 ready 773 ms、load 784 ms；根文档 390/390、844/844。入口 JS transferSize 50,908 B、CSS 7,417 B。
- [ ] 真实手机和真实大陆/海外 CDN 网络验收冷缓存、实际 RTT/抖动/丢包、资源完成时间、安全区和浏览器差异；本机限速结果不可外推为线上性能承诺。
- ✅ JS 估算百分比单调并限制在 72%；Vue mount、首帧和就绪阶段依次校准，只有实际发出 ready 才到 100%。
- ✅ 15 秒无 mount 时出现等待/重试选项；入口脚本失败切换错误提示与重试，无纯白/无限转圈界面。
- ✅ API 健康检查未纳入 Vue mount 门槛，失败仍可显示大厅并使用本地练习；在线状态另行提示。
- ✅ 启动壳自身只用内嵌 CSS 和文字，页面可在任何位图抵达前绘制；大厅背景/封面维持 CSS 底色占位并异步加载。
- ✅ 启动壳继续等待/重新加载按钮最小高度为 44 px，确保加载超时操作适用于触屏设备。
- [ ] 桌面、手机窄屏和安全区布局检查； reduced-motion、对比度、键盘焦点和屏幕阅读器状态可用。
- ✅ 生产构建验证 Pixi chunk 仍为独立延迟包，不进入大厅初始模块图；P0 预算与冷启动传输实测待做。
- [ ] 线上体验只用 production preview/部署构建作性能判断；Vite dev server 单独标识，不能作为发布性能验收结论。
