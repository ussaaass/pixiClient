# 后台与前台页面交互目录

版本：0.1（页面、弹窗和 DTO 交互设计基线）
范围：Admin 后台、代理 `/agent` 工作区、玩家 H5 大厅/钱包/社交/客服、游戏子厅/房间及十三张 PixiJS 牌桌。本文细化[管理后台功能规划](./管理后台功能规划.md)与[用户流程线框图](./用户流程与低保真线框图.md)，是后续 PC/Mobile 高保真、API DTO 和组件实现的页面目录。

## 1. Checklist 状态定义

- `✅ 设计闭环`：入口、主要动作、成功后去向、取消/失败状态、权限边界及 DTO 责任均已规定，可进入视觉稿/接口拆分。
- `⬜ 待补`：依赖尚未确认的业务值、策略或供应商；条目明确列出缺口，不能据此开始联调。
- `✅ 前端验收`：该范围内的页面结构、状态展示和可独立交互已实现并验证；不代表业务服务已接入。
- `🟡 前端部分`：仅实现部分页面/占位状态，仍有已设计的前端内容未落地。
- `⬜ 前端待做`：设计已完成，但页面代码尚未实现或验证。
- `✅ 服务端联调`：前端已与真实服务端契约完成成功、失败、权限和弱网路径联调；本地 mock 不计入。
- `⬜ 服务端待联调`：服务端契约、实现或联调证据尚缺；不得由本地假数据替代。

截至 2026-10-15，玩家侧已有可运行的 H5 启动壳、大厅、十三张桌面子厅和本地练习牌桌。十三张房间/匹配已实现离线 DDD 流程：共享 TypeBox 房间 DTO、纯领域状态转换、application use case、内存 `LOCAL_DEMO` repository 和房间 Sheet；可创建、快速匹配、加入、加练习机器人、准备、开局并从牌桌退出。房间号和其他座位名称会传入 Pixi 练习模块，但不代表真实联机。社区话题已实现本地文字帖子/回复演练；好友/私信已实现独立的 `LOCAL_BROWSER_SERVER` 离线流程：好友码/二维码与用户名查找、申请/通过/拒绝、好友列表、一对一文字私信和 IndexedDB 历史恢复。社交附件、举报/屏蔽、能力授权、域隔离与 Socket 投递仍未闭环。消息事项页已按来源聚合公告、本人资产流水、客服会话和好友申请，并提供失败重试与业务跳转；没有新增通知表或跨来源已读状态。玩家身份已使用独立 `LOCAL_BROWSER_SERVER` 流程，开发态可验证设备/密码登录、恢复二维码本机解密、设置用户名与密码、改密并撤销其他会话、邮箱/手机验证绑定与更换、TOTP 启用/关闭、TOTP challenge 与一次性备用码登录、登出及安全概览；恢复 QR 管理与备用码轮换、首次注册赠币、钱包账本/转账/兑换/提现申请、充值订单到本机模拟履约、客服文本工单/续写/关闭已形成离线流程。真实支付、USDT/TRON 充值、提现审核出款、客服附件与后台接单、战绩和邀请余下功能及生产 API/授权仍未闭环。任何演示 adapter 不能伪造正式身份、真实支付成功或生产配置发布；本地钱包、客服及私信只反映本 origin 的 IndexedDB 记录。下表区分设计、离线前端闭环和服务端联调；视觉完成不代表业务服务已上线。

2026-10-14 补充：Admin 开发态 `/admin/payments/mock` 已通过 `LOCAL_DEMO` application 和内存 adapter 闭环：创建测试订单、模拟成功/失败/超时/重复/错额事件并查看结果。模拟只改变当前页面会话内的测试投影，不访问 provider、订单 API、钱包、数据库或 Redis；它不代表真实支付或资产履约，生产构建不注册该路由。

每项功能均按“打开 → 读取/验证 → 确认 → 结果 → 失败/关闭 → 权限/审计”的闭环检查。三级页面优先作为 Dialog/Drawer；手机上改成全屏 Sheet，不为同一编辑流程复制第二套页面。复杂工作流（计算报告、客服会话、牌局、长表单）保留独立二级页面。

## 2. 页面壳、弹窗规范与共享组件

### 2.1 PC 与 Mobile 交互

| 模式 | 桌面端 | 手机端 | 使用范围 |
| --- | --- | --- | --- |
| `DetailDrawer` | 右侧 520–720px 抽屉 | 全屏 Sheet | 详情、记录、轻编辑、下线用户详情 |
| `FormDialog` | 中央 Dialog，窄表单 560px、复杂表单 800px | 全屏 Sheet；底部固定动作栏 | 新建/编辑、邀请、筛选条件 |
| `ConfirmDialog` | 小型确认框，危险动作必须显示对象/后果 | 底部确认 Sheet | 撤销、禁用、删除式隐藏、发布/退款拒绝等状态命令 |
| `WorkflowDialog` | 分步 Dialog 或独立子路由 | 全屏流程页 | 身份核验、提现审核、配置发布、账号恢复 |
| `ResultDialog` | 显示成功/部分成功/失败和下一步 | 全屏结果 Sheet | 异步任务、模拟报告、导入/发布结果 |
| `GameOverlay` | Pixi/H5 overlay layer | 安全区内全屏/底部 overlay | 牌桌设置、离桌确认、提交校验、重连和结算 |

弹窗打开后显示当前对象、状态与上下文；页面背景从键盘焦点及无障碍树隔离（Web 使用 `inert`），提交时禁用重复按钮并携带幂等 `requestKey`。网络超时不自动显示失败或重发新命令：先按原 key 查命令状态，再显示成功/可重试/待确认。关闭不等于撤销已提交动作。高风险操作必须有结果页并能回到原页面。Dialog 支持键盘 Esc/返回键；有未保存内容时二次确认。手机端键盘弹出时表单可滚动、确认按钮保持可达。

### 2.3 共享 DTO / 契约边界

### 2.4 离线前端流程与 DDD 边界

产品验收把“离线前端闭环”和“真实服务端联调”分开，但两者使用同一组领域 DTO/schema。Vue 页面不得把 HTTP 请求、领域规则、本地假数据和页面状态揉在一个组件内；流程按领域 application use case 调用 port，`LOCAL_DEMO` adapter 以隔离的内存仓储完成可交互演练，未来 `REMOTE` adapter 替换它并调用 HTTP/Socket.IO。命令结果回到相同的页面投影，不需重写 UI。

离线闭环不是展示一张“API 未接入”的空页面，也不是把一个成功 Toast 当作业务成功。每条用户可操作路径需要能完成演练、看到领域状态转移、取消/拒绝并返回来源；对身份、钱包、支付、RTP、资产和后台发布等高风险领域，必须明确处于演示模式，所有变动只保存在 demo sandbox，绝不能声称正式身份已认证、钱已到账或生产配置已发布。正式 JWT、真实 user capability 和服务端事实永远不能由本地 adapter 伪造。详细规则见[代码分层规范 §18](../02_architecture/代码分层与接口实现规范.md)。

目前首个完整房间切片位于 `apps/web/src/platform/rooms/`：`room-domain.ts` 负责等待/满员/准备/开局/离开状态规则，`room-application.ts` 通过 `RoomRepositoryPort` 编排用例，`offline-room-adapter.ts` 只持有本地演练数据；H5 通过 `ShisanshuiRoomFlow.vue` 消费 application。`packages/contracts/src/game-room.ts` 是共享传输 DTO/schema。开局时只把演练房号与其他座位的显示名映射为游戏模块的展示初始化参数；不把平台 room DTO、存储或用例直接耦合进 Pixi 规则引擎。替换为 remote adapter 时，页面和 use case 仍需补上服务端权威快照、权限、幂等 ACK、断线重连与命令状态查询。

设备端的低风险偏好是持久化客户端状态，不使用房间/社交演练的内存仓储：`packages/contracts/src/client-preferences.ts` 定义偏好 DTO 和更新命令，`apps/web/src/platform/preferences/` 做运行时校验、领域更新与 LocalStorage 适配；适配器迁移旧版两个布尔键。更新命令串行处理，避免快速切换两项时互相覆盖。此模式只适用于设备展示偏好，不可用于身份、余额、支付或生产配置。

每个页面的离线施工逐项覆盖：

1. 入口/直接 URL 能打开；初始 DTO 来自该领域本地 adapter，不在 Vue 模板塞业务 fixture。
2. 主动作经过 runtime schema 与领域 use case；有 loading、成功、业务拒绝、技术错误/重试和返回路径。
3. Dialog/Drawer 有取消及焦点归还；写操作的候选/确认/结果状态可走通，关闭不会暗示已经撤销已提交结果。
4. 同一 DTO/schema 和领域常量将由服务端复用；仅 adapter 注入点不同。本地数据与未来服务器数据互不混用。
5. 当前页所有看似按钮的控件都能动作，或作为明确的准入限制并给出可继续的替代路径；不留“点击后无响应/只能关页”的死胡同。

### 2.5 引导与环境边界的呈现

常驻导航、卡片和页面正文不放“API 未接入”“结构预览”“功能待服务端开放”等解释块；这类重复状态占用页面空间，也不帮助用户完成当前任务。环境身份只由 Admin/Agent 壳上的轻量标签表达，详细权限边界放到壳层问号按钮打开的 `PageHelpOverlay`。首次进入大厅/子厅的操作引导仍用可跳过的遮罩步骤，并记住完成状态；用户可从设置重新播放。规则、钱包、邀请等上下文说明使用对应动作旁的问号弹层。数据为空时只显示该功能真实需要的空态动作，不把“没有数据”写成“功能未接入”，也不展示伪造数据。

Admin/Agent 壳层帮助在桌面顶栏及移动顶栏均可打开，Esc、遮罩点击和关闭按钮可退出；焦点在关闭后回到触发按钮。业务空态中的安全事实可以保留为简洁的准入状态；超过一段简短解释的操作规则应移入就近帮助弹层，不重复放进侧栏或页面横幅。查询服务状态只记在本目录和领域 SDD；页面不使用专门的 API 未接入徽标/横幅，空列表用“暂无记录”表达。

`LOCAL_DEMO` 只证明前端工作流及领域规则交互，不计真实 API/权限/Socket 弱网联调。页面 checklist 继续保留 `前端实现` 与 `服务端联调` 两列；前者还要标记“离线流程闭环”，不因空态视觉完成而打勾。

## 7. 公共弹窗状态与异常闭环

所有 overlay/dialog 必须覆盖以下状态。省略其中任一状态，功能不得标记设计完成：

| 状态 | UI 行为 | 用户可做的事 |
| --- | --- | --- |
| `LOADING` | 保留上下文，禁重复提交；显示最后更新时间 | 等待或安全取消读取 |
| `READY` | 展示完整对象、金额/单位、费用、权限范围和确认动作 | 确认、编辑或关闭 |
| `SUBMITTING` | 原 requestKey 固定，阻止二次操作 | 等待，不创建另一笔请求 |
| `SUCCEEDED` | 展示结果、关联 ID、下一步和返回入口 | 查看详情/返回 |
| `VALIDATION_FAILED` | 字段级错误，保留用户输入 | 修正输入 |
| `DENIED` | 展示通用授权/资格失败，不泄漏上游或其他用户信息 | 返回或联系支持 |
| `UNKNOWN` | 显示“正在确认结果”，用原 requestKey 查询状态 | 重试查询，不重复下单/提交 |
| `OFFLINE` | 标明本地草稿与最后服务端状态 | 恢复网络后查询/同步 |
| `STALE_VERSION` | 展示新旧版本差异并刷新数据 | 重新确认或放弃 |
| `CANCELLED/EXPIRED` | 清除临时 quote/验证码但保留可重填普通字段 | 重新开始 |

## 8. 设计闭环 Checklist

每个功能进入高保真/接口联调前逐项过关；设计列说明方案是否闭环，前端列只记录真实页面代码及对应浏览器验收，联调列只记录真实服务端上的契约/权限/错误路径。三类证据互不替代。

## 9. 已知非阻塞待定项

玩家端与 Admin 的低频操作说明使用按需帮助蒙层；大厅/子厅发现性说明使用目标高亮蒙层。资金、隐私、权限和配置发布等影响决策的边界仍紧邻相应操作显示。具体组件清扫及范围见[交互引导需求分析与 UI/UX 设计](./交互引导需求分析与UIUX设计.md)。

- ⬜ Admin 手机端是否允许所有高风险变更，还是只读/二次验证；当前默认高风险写操作可用但强制 TOTP/确认。
- ⬜ 各 game handler 自己定义的 Slot/捕鱼/开奖/麻将胡了弹窗内容和 DTO；接入对应游戏时补充，不重复平台壳。
- ⬜ 社交消息保存期限、帖子/附件最大体积、好友数及频率阈值；控件已预留配置错误与超限状态。
- ⬜ 真实支付 provider 的字段、审核/出款 API 与异步状态；Mock 控制台只覆盖本机内存状态演练，真实 provider 接入时再加 adapter 专属状态与签名事件联调。
