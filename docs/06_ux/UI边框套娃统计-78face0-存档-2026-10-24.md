# UI「边框套娃」统计（`78face0`，2026-10-24）— 历史存档

> **⚠️ 本文件是历史存档，不要作为整改基线。**
> 审计版本是 `78face0`；主工作区已到 `a62c22d`，两端有 35 个文件变化（+5,778 / −1,972 行）。
> 本文存在四处不达标：后台称「20 条路由覆盖」实为抽样（路由表 47 条页面路由）、运行时数字无脚本与原始数据留存、「互不复用的类名」无计算定义、链路用 `>` 写成直接父子关系却省略了无边框的中间节点。
> **当前基线见 [`UI边框套娃统计-a62c22d-2026-10-24.md`](./UI边框套娃统计-a62c22d-2026-10-24.md)**，工具与原始数据在 `tools/ui-audit/`。本文保留仅为对照，便于核对基线报告第七节的逐项差异。

统计对象：`apps/web`（玩家端）与 `apps/admin`（后台）当前 HEAD 的样式与真实渲染 DOM。
统计口径：**表面层（surface）= 有可见边框或阴影的容器**（div/section/article/form/ul 等）；控件（button/input/select/a）与表格单元格（table/tr/td）单独计数，不混入容器深度。深度按「最近的有边框祖先容器」逐级累加，最外层为 1。

## 一、结论

1. **深度不算失控，但密度很高**：同屏最深 3 层，绝大多数页面稳定在 2 层；问题不是「十层套娃」，而是**每层都各自造了一个框**。
2. **宽度失控**：两端共 **748 条「边框+背景」规则、666 个互不复用的类名、193 种边框颜色写法**，全站没有一个 `.card` / `.panel` / `.surface` 基类。
3. **最刺眼的是后台**：20 个页面共 161 个容器边框、95 个控件边框、**125 个表格单元格边框**；单页最多同屏 **39 个边框元素**（`/admin/referrals`）。

## 四、真实套娃链（取自 DOM）

| 链路 | 层数 | 出现页面 |
| --- | --- | --- |
| `section.game-row > article.game-card > div.game-art` | 3（引导态）/ 2（常态） | 玩家大厅 |
| `section.player-profile-card > div.player-profile-overview > div.player-profile-avatar` | 3 | `/profile` |
| `section.agent-operations-panel > div.agent-downline-table-wrap > td > button` | 4 个边框元素 | `/agent/downlines` |
| `div.system-work-panel > article.system-config-row > button` | 3 | `/admin/system` |
| `section.ops-monitor-panel > tr > button.ops-row-detail` | 3 | `/admin/referrals` |
| `section.game-catalog-panel > div.el-select__wrapper` | 2 | `/admin/games` |

典型形态是三种叠加：**面板框 + 行/单元格框 + 控件框**；后台的表格把「单元格全边框」直接压在「面板框」上，是最容易产生「框套框」观感的来源。

## 五、根因

1. **没有表面基元**：0 个共享卡片类，666 个私有类各写一遍 `border + background + border-radius`。
2. **颜色不是令牌**：193 种边框色写法（含大量 `#d9b66c35` 这类一次性透明度变体），只有 7 个 CSS 自定义属性。
3. **结构叠三层**：面板本身有框，内部行/单元格再有框，按钮/输入再有一层框；后台 125 个单元格边框放大了这个问题。
4. **圆角各写各的**：两端各 12 种取值，视觉上无法形成统一的「一层」感知。

## 六、整改建议与量化目标

| 优先级 | 动作 | 目标值 |
| --- | --- | --- |
| P0 | 定义 `--surface-border / --surface-radius / --surface-bg` 三个令牌 + 一个 `.surface` 基类；规定「页面 > 面板 > 条目」最多两级框，第三级改用间距或分隔线 | 边框色 193 → ≤ 8；圆角 24 → ≤ 4 |
| P0 | 后台表格改为「行分隔线」而非单元格全边框 | 单元格边框 125 → 0；单页边框元素 ≤ 25 |
| P1 | 把 666 个私有卡片类收敛为约 12 个语义类（panel / card / row / chip / field / toolbar…） | 私有类 666 → ≤ 30 |
| P1 | 控件边框统一到 `--control-border`，同屏控件边框不超过 10 个 | 控件边框 95+65 → ≤ 40 |
| P2 | 把本次统计脚本固化为 `tools/ui-audit` 门禁：`maxDepth ≤ 2`、同屏边框元素 ≤ 25、边框色种类 ≤ 8 | CI 阻断回归 |

## 七、复现方法

- 前端以开发模式构建并用静态服务器托管（`vite build --mode development`），保证 `import.meta.env.DEV` 分支与本地 IndexedDB 装配生效；后台路由守卫在开发态放行。
- 用 headless Chromium 依次访问各路由，先关闭新手引导浮层，再读取 `getComputedStyle` 统计边框/阴影/背景与祖先链。
- 视口：桌面 1440×900、移动 390×844；每页滚动到底再回到顶部，排除懒加载遗漏。
- 局限：只统计可见元素；装饰性图标边框（如圆形头像）会被计入容器/控件；本次未覆盖真实设备与 Safari/WebKit。
