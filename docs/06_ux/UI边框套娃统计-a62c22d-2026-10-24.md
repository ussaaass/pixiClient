## 一、版本与覆盖范围

先把「测了什么、没测什么」说清楚，避免把抽样当全量。

### 后台 `apps/admin`

`apps/admin/src/router.ts` 共有 **49 条 `path` 记录**（39 条字面量 + 10 条由 `domainEntries` 生成的域路由）。其中 `/` 与 `/:pathMatch(.*)*` 是纯跳转，剩 **47 条页面路由**（含 1 条仅开发态：`/admin/payments/mock`）。

| 项 | 数量 | 说明 |
| --- | --- | --- |
| 路由表页面路由 | 47 | 已全部纳入清单 |
| 实际可测 | **47** | 全部渲染出目标页面并完成测量 |
| 被重定向 / 失败 | 0 | — |

> 记录一处自查修正：首轮跑测时 4 条游戏配置路由（`/admin/games/:gameKey/difficulties/:difficultyKey/{config,expectation}` 与 `/agent/...` 同名两条）全部落到 `/admin/login`。当时误判为「被路由守卫拦截」，实际原因是**路由清单把字面量段 `difficulties` 漏掉了**，拼出的 URL 匹配不上，被 `/:pathMatch(.*)*` 兜底到登录页。修正清单后 47 条全部可测。这类错误正是「没有原始数据就无法复核」的典型代价——见 `tools/ui-audit/routes.json` 的 `dynamic` 标注。

## 二、统计口径

完整定义见 `tools/ui-audit/README.md`，要点：

| 名词 | 定义 |
| --- | --- |
| 容器 | `div/section/article/main/aside/header/footer/nav/form/ul/ol/dl` 中**有可见边框或阴影**的元素 |
| 控件 | `button/input/select/textarea/a/summary`（或 `role=button`）中有可见边框或阴影的元素 |
| 表格线 | `table/thead/tbody/tr/td/th` 中有可见边框的元素 |
| 填充块 | 有非透明背景色且圆角 ≥ 8px 的任意元素 |
| 深度 | 向上数「有边框容器祖先」的个数，自身计 1；**只数容器**，不把按钮/单元格算进层级 |
| 嵌套 | 深度 ≥ 2 的容器 |
| 同屏边框元素 | 容器 + 控件 + 表格线（不含填充块，避免与容器重复计数） |
| 可见 | 非 `display:none`、非 `visibility:hidden`、`opacity≠0`、宽 ≥ 40px 且高 ≥ 24px |

样式层口径（`css-stats.mjs`）：

- `cardRules`：同时设置非 `none` 边框与非透明背景的规则数；
- `cardClasses`：上述规则选择器中出现过的**不同类名数**。这只代表「命名分散程度」，**不能证明这些类名没有被复用**；
- `borderColors`：边框声明里的颜色字面量去重数（含 `#hex`、`rgb()/rgba()`、`hsl()`、`var(--x)`）；
- `radiusValues`：`border-radius` 取值按文本去重数（`10px` 与 `10px 10px 10px 10px` 记为两个值）。

## 三、结论

1. **深度没有失控，密度很高**：两端同屏最深都是 3 层，绝大多数页面停在 2 层。问题不是「十层套娃」，而是**每一层都各自造了一个框**。47 个后台页面里只有 3 个到过 3 层（`/admin/payments/mock`、`/admin/admin-users`、`/agent/social`），玩家端只有 `/profile`。
2. **后台的主要刺眼点是表格全格边框，不是容器嵌套**：163 条表格线占后台边框元素总数（696 = 361 容器 + 172 控件 + 163 表格线）的 23%，且集中在少数页面——`/agent/downlines` 单页 28 条、`/admin/referrals` 与 `/admin/support/conversations` 各 18 条。`/admin/referrals` 同屏 39 个边框元素，其中 18 个来自单元格。
3. **边框颜色不是令牌，尤其是玩家端**：玩家端 127 种边框色里 **106 种是 8 位 hex（带 alpha）**，绝大多数是 `#e1c2763b`、`#e8c77d2a` 这类只差两位透明度的写法。后台反过来——107 种里 104 种是 6 位实色，其中 **90 种与另一种颜色的 RGB 三通道差值都 ≤ 8**，即肉眼几乎无法区分的一堆浅灰（`#e5e8ed` / `#e5e9ef` / `#e6e9ef`）。
4. **没有表面基元**：两端共 573 条「边框 + 背景」规则、576 个出现过的类名，仍然找不到 `.card` / `.panel` / `.surface` 这类共享基类；CSS 自定义属性两端合计 7 个。

## 七、与 `78face0` 版报告的差异

上一份报告（`UI边框套娃统计-78face0-存档-2026-10-24.md`）审计的是 `78face0`，现已降级为历史存档。两个版本之间 `apps/web` + `apps/admin` 有 **35 个文件变化、+5,778 / −1,972 行**，所以旧报告的数字不能直接和本文件对比。差异来源有三类：

| 类别 | 旧报告 | 本文件 | 原因 |
| --- | --- | --- | --- |
| 版本 | `78face0` | `a62c22d` | 35 个文件变更 |
| 后台覆盖 | 20 条（称「路由覆盖」） | 47 条可测 / 47 条页面路由 | 旧版是抽样，且表述夸大为全量 |
| 玩家端覆盖 | 7 条（未说明是样本） | 20 条可测 / 22 条静态 | 同上 |
| 边框色 | 101 / 92（合计 193） | 127 / 107（合计 234） | 口径改为「含 `var()` 与 `rgba()` 的去重字面量」，且已明确定义 |
| 圆角取值 | 各 12（合计 24） | 31 / 23（合计 54） | 改为按文本去重，不再手工归并近似值 |
| 类名 | 「666 个互不复用的类名」 | 576 个出现过的类名 | 旧表述过强：类名出现次数 ≠ 未被复用 |
| 后台容器 | 161 | 361 | 覆盖 20 → 47 页，非同一总体 |
| 后台表格线 | 125 | 163 | 同上 |

**结论层面没有推翻的**：边框层次确实需要整理、后台表格全格边框确实是最刺眼的一项、确实没有共享表面基类。**被修正的**：旧报告的绝对值不能当基线，覆盖率被夸大，「互不复用」是不成立的强表述。

需要说明的是，本次全量跑测过程中**我自己也犯过一次同类错误**：首轮清单把游戏配置路由的字面量段 `difficulties` 漏掉，拼出的 URL 匹配不上、被 catch-all 兜底到登录页，于是误判成「4 条路由被守卫拦截的产品缺陷」。用浏览器直接探一遍最终 URL 与控制台才定位到是清单写错。这件事说明：**「跑出异常数字」和「产品有缺陷」之间隔着一次复核**，任何没有原始数据支撑的异常结论都不该写进报告。

## 八、整改建议

以下目标是**设计目标**，用于排期与验收讨论，**不建议直接做成 CI 硬门禁**：这些指标受页面数据量影响（表格行数、消息条数一变，同屏边框元素就变），做成阻断会让流水线随机变红。若要进 CI，应先用固定数据种子跑出稳定区间，再设「不得比基线更差」的宽松阈值。

| 优先级 | 动作 | 设计目标 | 现状 |
| --- | --- | --- | --- |
| P0 | 后台表格改「行分隔线」替代单元格全格边框 | 表格线 → 0 | 163 条，集中 5 个页面 |
| P0 | 定义 `--surface-border` / `--surface-bg` / `--surface-radius` 三个令牌 + 一个 `.surface` 基类 | 边框色 ≤ 8 种 | 234 种（玩家端 106 种是 alpha 变体，后台 90 种是近同浅灰） |
| P1 | 收敛圆角取值到 4 档（如 8/12/16/999） | 圆角 ≤ 4 种 | 54 种 |
| P1 | 面板内不再给控件加第二层边框（`el-select__wrapper` 等） | 面板内控件边框 → 0 | 后台 172 条控件边框 |
| P1 | 移动端大厅减少同屏带框元素 | 单屏边框元素 ≤ 25 | 移动 `/` 50 个 |
| P2 | 玩家端 alpha 边框色归并到 2–3 档透明度 | alpha 变体 ≤ 3 | 106 种 |

优先动 `/admin/referrals`、`/agent/downlines`、`/admin/support/conversations` 三个表格页：它们合计 64 条表格线，占后台总数的 39%，改动面小、观感收益最直接。

## 十、局限

- 只统计**可见元素**；圆形头像等装饰性边框会计入容器/控件，会让数字偏高。
- 统计对象是**开发模式**页面。脚本会先点掉「跳过/知道了/关闭」再测量，但自定义浮层可能漏关；`/admin/payments/mock` 本身只在开发态存在。
- 数据量直接决定结果：同一页面表格从 5 行变 50 行，边框元素会成倍变化。跨版本比较必须说明数据状态。
- `cardClasses` 只反映命名分散程度，不反映复用情况；「是否有共享基类」是人工检索结论（两端均未找到 `.card` / `.panel` / `.surface`）。
- 未覆盖真实设备、WebKit 与生产产物；移动端只测了 390×844 一档。
