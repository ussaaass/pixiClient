### 2.3 执行环境坑（会误导判断）

1. **并行跑 `pnpm typecheck` 时 `apps/web`、`apps/admin` 的 `vue-tsc` 会被 SIGKILL**（内存不足）。**后续复核更正：这不是固有限制**——串行/独占执行时 `pnpm typecheck` 一次跑完 8 个目标耗时 4m18s、exit 0。当时的 SIGKILL 是我同时挂着全量测试造成的本机内存压力，不要据此判定类型错误。
2. **`pnpm test` 一次性递归会在 `apps/server` 处 abort**（`ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`），后面的包根本不执行。要拿全量结果必须加 `--no-bail` 或逐包单跑。
3. **`apps/web` 测试 12 分 40 秒**，其中 happy-dom 环境创建占 **67%（483s）**，28 个测试文件各建一次环境。这会让"本地跑一遍测试"成本极高，也是 CI 30 分钟超时的隐患。
4. macOS 无 `timeout` 命令，别在脚本里用。

## 3. 两个真实缺陷（非格式问题）

### D1（阻塞）：`apps/server/src/migrations.test.ts` 顶层 import 迁移器

- **现象**：`pnpm test` 在 server 报 `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'umzug' imported from .../migrator.ts`，测试文件直接 not ok。
- **根因**：文件第 4~5 行在**模块顶层** `import { createMigrator }` / `getSequelize`。即使 `MIGRATION_TEST` 未设置、用例本应被 `skip`，ESM 加载阶段就已抛错，`skip` 根本没机会生效。
- **影响**：只要依赖缺一个，整个 server 测试套件红，而不是"跳过"。这是设计上的脆弱点，不只是本次缺依赖。
- **修法**：把 `createMigrator` 改为用例体内 `await import('...')`；或在文件顶部先判 `enabled`，未启用时直接 `test.skip` 一个空用例并不导入迁移器。
- **装好依赖后本条会"自然消失"**，但隐患仍在，建议一并修。

### D2（既有，与本次改动无关）：`apps/web/src/PlayerSocialProfile.test.ts:48` 确定性失败

- **现象**：`Error: UI state did not settle in time`，卡在 `await waitFor(() => onOpenMessages.mock.calls.length === 1)`；单跑 3 秒必挂，不是时序抖动。
- **根因链**：测试第 26 行把 `friends.openConversation` mock 成 `vi.fn()`（返回 `undefined`）→ 组件 `PlayerPublicSocialProfile.vue:85` 写的是 `const { conversationId } = await props.friendsApplication.openConversation(userId)` → 解构 `undefined` 抛 `TypeError` → 第 86 行 `emit('openMessages', ...)` 永不执行。
- **归属判定**：`PlayerPublicSocialProfile.vue` 与 `PlayerSocialProfile.test.ts` **都未被本次改动触碰（等于 HEAD 状态）**，唯一相关改动是 `social-application.ts` 的 import 路径换成 `@gameing/domain/social`，且该域文件与 HEAD 版本 `diff -w` 后**只有格式差异、无语义差异**。因此这是**既有陈旧测试**：组件契约后来加了 `conversationId`，测试 mock 没跟上。
- **修法**：mock 改为 `vi.fn(async () => ({ conversationId: 'conv-1' }))`。

### 7.2 装依赖后新暴露的 3 个缺陷（全部已修）

依赖缺失时这 3 个问题都被"模块找不到"掩盖，属于**典型的"不跑就不知道"**：

1. **`config.ts` TS2375（`dialectOptions`）**。`Options['dialectOptions']` 的类型是 `object | undefined`，而 `tsconfig` 开了 `exactOptionalPropertyTypes`，把它断言成可选属性再赋值等于给可选属性显式赋 `undefined`，直接报错。
   **修法**：断言目标改为 `NonNullable<Options['dialectOptions']>`，运行时取值不变。
2. **`migrator.ts` TS2322（logger 形状不兼容）**。Umzug 的 `logger` 要求 `Record<'debug'|'info'|'warn'|'error', (message: Record<string, unknown>) => void>`，而项目 `Logger` 是 `(message: string, fields?: LogFields) => void`。
   **修法**：新增 `adaptLoggerForUmzug()`，把 Umzug 回调里的 `event` 提成 message、其余键作为结构化字段下传（而不是 `JSON.stringify` 成一段无法检索的字符串）。日志里现在能看到 `迁移事件：migrating` / `migrated` 带 `name`、`durationSeconds`。
3. **`agent-announcement-domain.ts` `no-control-regex` error**。这是**上一轮 Prettier 全仓格式化引入的回归**：`return` 被折成多行后，`eslint-disable-next-line` 落到了上一行、不再覆盖真正的正则行，同时自身变成 "unused directive"。
   **修法**：把控制字符正则提成模块级常量 `controlCharacters`，disable 注释紧贴单行声明，Prettier 无法再把它折开。同时与已有的 `unsupportedClaims` / `externalMarkup` 风格统一。

### 7.3 D1、D2 的实际修法

- **D1**：`migrations.test.ts` 去掉迁移器/连接的顶层 `import`，改为用例体内 `await import(...)`；`readColumns()` 改为显式接收 `sequelize` 实例。`sequelize` 只保留 `import type`（编译期擦除）。现在依赖缺失或未设 `MIGRATION_TEST` 时，用例正常 `skip` 而不是把整个套件带红。实测：`11 tests / 10 pass / 1 skipped`。
