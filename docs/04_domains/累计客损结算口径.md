# 代理客损模式边界

**状态：已确认的业务边界。** 本文取代早期“平台计算累计客损并在提现时给上级返点”的方案。平台不参与客损模式用户的余额提现，不取得其线下充值/提现数据，也不计算、记账或发放客损返点。

## 客损模式

`user.reward_type` 描述该用户作为上级时采用的返佣模式：`RECHARGE=1`（默认）或 `LOSS=2`。客户适用哪种资产入口限制由其直属上级的 `reward_type` 决定。

对于直属上级为 `LOSS` 的客户：

- 代理线下自行维护充值、提现及客损差额，并在线下结算客损返点。计算公式及线下资金安排属于代理与客户之间的结算，不进入平台数据库或平台资产账本。
- 平台不展示金币购买、金币兑余额和平台余额提现入口，也拒绝客户创建金币购买订单及不允许的外部金币入账。
- 客户可以由当前邀请链中的直属至第四级上级转入金币。该转账作为平台内金币资产操作记录，供币人必须是该客户当前绑定链上的祖先；转账不算充值、不触发平台充值返点，也不代表平台经手其线下充值或提现。
- 游戏结算、平台赠币和必要的账务冲正仍按各自的平台业务规则处理。赠币增加流水要求，但不追踪赠币来源，也不把牌局输赢作为平台客损返点数据。

对于直属上级为 `RECHARGE` 的客户，平台按实际支付成功的金币购买订单计算充值返点。当前配置的层级比例为直属至第四级 10%/8%/5%/3%；上级需为充值返点模式才取得对应奖励，奖励在平台余额入账并冻结 2 天。

## 流水资格与资产记录

赠币与普通金币使用同一金币余额。每笔赠币按全局配置增加流水要求；每局已结算有效下注按下注金额累计流水，不按输赢计算。流水未完成时禁止金币转出和提现。`gift_grant` 记录赠币及其要求额，`round_player.wager_coins` 提供有效下注额；唯一的 `turnover_state` 行保存该用户总要求和剩余要求。流水要求不改金币余额、不冻结资产，也不需要把某局下注分配到某一笔赠币。

上级供币使用 `asset_operation` 和 `asset_entry` 记账，并记录发起供币的用户。系统账户按普通金币转账规则作为资产账本的一方；供币交易不创建 `order`、`withdrawal` 或返点记录。平台不保存客损公式所需的代理线下充值、提现总额或历史处理高位。

## 数据库边界

平台 schema 不包含 `customer_loss_state`、`customer_loss_event`、`customer_loss_settlement`，也不包含追踪赠币来源或转账来源消耗的补贴表。`referral_reward_allocation` 只记录平台实际发放的充值返点。`withdrawal` 只处理平台支持的余额提现，不用作代理线下客损结算事件。

详细实体及表用途见 [数据库设计 SDD](../05_data/数据库设计SDD.md)；邀请关系、返佣模式及五层关系快照见 [邀请归因返佣与数据规范](./邀请归因返佣与数据规范.md)。
