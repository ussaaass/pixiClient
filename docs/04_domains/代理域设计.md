# 代理域设计

阶段：代理后台与游戏/社交隔离的领域设计。代理本身仍是普通 `user`，不创建 `agent` 或 `agent_user` 身份表；`agent_domain` 表达代理获批后拥有的运营范围、权限和配置边界。用户资料、登录、安全、钱包、邀请关系仍归各自领域管理。

## 1. 目标与术语

用户可以申请成为代理。Admin 审核通过后，在该用户之下开通一个代理域，并逐项授予已登记的代理后台能力。代理通过专用 Agent Web 页面管理被授权的数据与配置。一个代理域支持：

- 查看其授权范围内下线的完整业务资料，包括资产余额与流水、充值/提现订单、游戏局明细、邀请关系和运营统计；密码、TOTP 秘钥、恢复码、设备认证秘密及其他登录凭证永不向代理开放。
- 在平台批准的参数边界内，为域内游戏/难度创建配置候选、运行 RTP/分布模拟、发布域级配置。
- 发布域内广播；浏览域内帖子、跟帖、话题、好友和私聊。不同域之间默认互不可见、不可交互。

`agent_domain` 是权限与产品数据的租户范围。它不拥有用户资产，不替代 `referral_binding`，也不是独立登录主体。代理使用同一个 `user`、JWT/session 和 `role_type` 常量体系。

## 2. 身份、申请与域生命周期

```text
普通 user
  └─ 申请代理 → 待审核
       ├─ 用户撤回 → WITHDRAWN，保留 agent_domain 实体
       ├─ Admin 拒绝 → 普通 user，记录审计
       └─ Admin 批准 → 创建 agent_domain，授予 capability codes
                            ├─ Active：可使用获批功能
                            ├─ Suspended：只读或完全拒绝，由状态策略决定
                            └─ Revoked：撤销代理能力，用户账号仍保留
```

批准/撤销不改变用户 ID、邀请关系、钱包或登录凭证。`role_type` 只表明用户身份类别；每个 API 同时校验 `user.role_type`、`agent_domain.status`、域权限代码和资源范围，不能仅凭 JWT 中的旧 role/permissions 声明放行。Agent 登录沿用 user 的 JWT，不签发一种身份不同的代理 token。

申请记录不是第二份用户记录。首版申请可作为 `agent_domain` 的 `PENDING_REVIEW` 状态记录；用户撤回后状态转为 `WITHDRAWN=5`，Admin 拒绝后状态转为 `REVOKED=4`，均保留该实体。状态常量从 1 开始：PENDING_REVIEW=1、ACTIVE=2、SUSPENDED=3、REVOKED=4、WITHDRAWN=5。权限变更、暂停、恢复、批准和撤销写入不可变 `admin_audit_event`，包含目标 user、agent_domain、前后 capability 快照、操作者和理由。

## 3. 数据范围和下线解析

不新增代理成员树表。邀请关系 `referral_binding.parent_1_user_id`…`parent_4_user_id` 是下线关系唯一事实来源；代理根用户的下线可通过索引化的四级祖先列查询。游戏/社交授权不得信任客户端传入的 `agent_domain_id`、用户 ID 列表或筛选条件。

推荐的归属规则：用户属于其本人/祖先链上最近的、状态为 Active 的代理域；若链上没有代理域则属于平台公共范围。一个用户在同一时刻只有一个有效代理域。代理域树由邀请关系隐式形成，子代理可建立嵌套域。

隔离优先于上级的全量可见性：子代理域用户的帖子、对话、公告、游戏参数和明细数据不向父域开放。父代理可以查看子代理层级与脱敏汇总（如人数、汇总投注/活跃统计），不能进入子域的用户明细和运营内容；Admin 有独立的全平台授权。对于代理自己域内直接管理的下线，授予 `AGENT_DOWNLINE_READ` 后可以查看完整业务明细，包括金币/余额及冻结、资产分录、充值/提现、牌局/投注、返佣与流水要求。该权限不包含登录密码、TOTP 秘钥/恢复码、设备认证秘密、二维码恢复秘密、收款密钥或内部风控凭证。导出能力单独授权、审计和限流。

换绑会改变被邀请用户及受影响子树的有效域。邀请链、收益投影及迁移任务在绑定事务中提交；资产、游戏局、支付、邀请返点和不可变审计是业务历史，永远保留原始操作者/关系快照，不随域迁移改写。全部社交内容随换绑迁移：帖子、整条帖子回复树、话题归属、好友/屏蔽关系、相关举报和私聊历史都进入新域。若私聊另一方留在旧域，整段会话及所有消息仍随换绑用户迁入新域，旧域成员失去该会话读取权和继续发送的能力；迁出用户与其新域代理可查看迁移后的历史，对话暂时只读；以后若双方同域，再恢复正常互动。话题在目标域创建/复用并重绑迁移帖子。绑定提交立即按最新关系撤销旧域代理授权；域查询同时排除与迁移中用户关联的社交对象，不能等物理搬完才关闭旧域读取。迁移完成前阻止受影响用户进行社交读写，避免部分迁移内容泄露或出现不一致。通过现有 `outbox` 为每个有效域变更的用户排可靠迁移任务，worker 分批、幂等更新社交 scope；全部实体计数校验成功后任务才完成并恢复访问。重复换绑须等前次迁移完成。迁移不与资产/邀请关系锁保持在同一长事务中。换绑提交后失效 Redis capability/domain cache，并推送 `capabilities.updated`。

## 4. 权限设计

采用 Admin 勾选 capability code，而不是给代理任意 Admin 路径。capability 是后端代码中的常量/注册目录，前端只展示服务器返回的能力。建议首批代码：

| Capability | 允许的操作 | 明确不包含 |
| --- | --- | --- |
| `AGENT_DASHBOARD_READ` | 本域运营总览 | 全平台总览 |
| `AGENT_DOWNLINE_READ` | 查看直接管理范围下线完整业务资料、资产/支付/游戏明细及聚合 | 修改关系、查看密码/TOTP/恢复码/设备认证秘密/私钥 |
| `AGENT_GAME_CONFIG_READ` | 查看本域有效游戏配置与版本 | 读取其他域草稿 |
| `AGENT_GAME_CONFIG_SIMULATE` | 使用无副作用计算器试算域配置候选 | 生产牌局/用户输赢数据作为试算输入 |
| `AGENT_GAME_CONFIG_PUBLISH` | 发布通过约束与计算的本域候选 | 修改平台基础值/越过硬边界 |
| `AGENT_ANNOUNCEMENT_MANAGE` | 创建、预览、撤回本域广播 | 全平台广播 |
| `AGENT_SOCIAL_MODERATE` | 管理本域话题、帖子与回复（仅显式授予） | 读取客服 IM |
| `AGENT_SOCIAL_READ_PRIVATE_MESSAGES` | 查看本域用户好友关系、私聊会话与消息历史 | 读取其他域或客服 IM |
| `AGENT_EXPORT_READ` | 导出已获准范围内字段 | 默认隐含导出所有权限 |

权限检查顺序：认证 user → `agent_domain` 状态 → capability code → 资源归属域 → 字段级数据权限 → 审计/限流。每条 HTTP、Socket.IO、导出、计算和变更 API 均服务端校验。菜单隐藏不算授权。代理发布配置、广播撤回、查看下线业务明细、导出及读取私聊均记录操作者、域、目标资源、时间和动作；私聊读取记录不得包含消息正文。

下线敏感明细采用带请求 body 的 `POST /api/v1/agent/downlines/:userId/detail-reads`，因为读取会产生不可变审计副作用。请求必须有登记的 `purposeCode` 和唯一 `requestKey`；客服工单用途还要求 `caseReference`。服务端先校验身份、域、`AGENT_DOWNLINE_READ` 与目标归属，再原子写 `agent_audit_event`，之后才返回允许的详情字段；同一 requestKey/目标/目的重试返回同一读取结果，不得重复写审计，requestKey 复用于不同参数则冲突。目标不存在或越域也记录 DENIED 后以统一不可枚举响应拒绝，不能因 UI 已过滤而省略服务端校验。目的代码和结果常量由共享 contracts DTO 定义；本地开发 adapter 只在 Admin 专用 IndexedDB 模拟同一 append-only 行为，不充当生产授权或审计凭证。

Admin 可以修改授权代码；只允许选择已登记代码，不能填写任意 path、SQL 或 JSON 规则。Admin 自身的 `user.permissions` 与 `admin_permission` 仍只管理平台 Admin 路由，不与代理 capability 混用。

## 5. 域级游戏配置与期望计算

平台 `game_config` 继续保存游戏/难度基准配置和全局硬约束。域级配置是可选 override，解析顺序为：

```text
平台 system/game/tier 基础值
  → 对应 agent_domain 的 game/tier override
  → 本局/投注开始时锁定最终解析快照
```

Agent 只能修改该游戏 handler 明确登记的可调参数，且每个值必须落在 Admin 配置的上下界、资金/奖池约束和数学模型版本允许范围内。无法由数学模型约束的参数不开放给代理。模拟器运行 1000/10000 轮只用临时虚拟样本，不读真实玩家损益、不写业务数据、不扣钱。

计算器报告展示域、游戏、难度、基础配置、域配置、math model 版本、样本数、RTP、轮空/大奖率、方差、结果分布和区间。候选无解、样本不足或精算/模拟偏差超限时禁止发布。通过全局参数范围、硬约束和模拟校验后，由获授 `AGENT_GAME_CONFIG_PUBLISH` 的代理即时发布；不另等 Admin 逐次审批。每次发布仍写不可变审计及完整配置快照，平台 Admin 可暂停域 override 或回滚到先前有效配置。发布仅作用于该域新开的游戏局/新注单；已开始实例保持原快照。

配置生命周期不另建草稿、配置版本或模拟结果表：代理编辑中的候选仅存在当前页面状态；模拟任务及逐轮虚拟结果仅存在计算 worker 内存，模拟结束返回完整报告，不产生业务写入。获授权代理确认发布时，在一个事务内重新校验域状态/capability、基准配置、参数白名单与边界，再更新 `game_config` 当前行，并追加一条不可变 `agent_audit_event`。审计快照保存游戏/档位 scope、每个变更 key 的配置行 ID/类型/发布前字符串/发布后字符串、math model 与配置 schema 版本、样本量及报告摘要/摘要哈希、操作者原因和请求键；不保存 1000/10000 轮逐局明细。任一检查或写入失败，配置和审计一起回滚。一个 scope 的多 key 发布作为同一事务和一份变更快照，禁止部分生效。

每个 `game_config` key 仅保留当前有效值；审计事件是配置变更历史。撤销域 override 通过停用/软删除该域对应配置行并写同类审计，使解析回退到平台基准；回滚不是改写旧审计，而是把选定审计中的旧值作为一次新的配置发布，并生成新的审计事件。新牌局/注单将最终解析后的完整值、平台及域来源、游戏 handler/schema/math model 版本写入既有 `round.rules_snapshot` 或相应游戏实例快照，之后不受配置更新影响。模拟报告如仅供预览不持久化；发布审计只留足以说明决策和复核结果的摘要。

域配置不得按单个玩家、设备、账号行为、输赢序列或资金情况定制结果；同一配置版本对域内所有适用玩家一致。域间 RTP 差异必须由平台设定合法产品边界和可审计说明，不能通过隐藏的用户级概率操纵实现。全局 Admin 保留暂停某域配置、回滚到既有合规版本的能力。

实现上不另造计算器：复用 `GameMathModel`、模拟 worker、配置 schema、报告和审计流程，只给任务增加经服务端确认的 `agent_domain_id` scope，并强制候选使用域的基准版本和硬边界。

### 浏览器离线演练的施工契约

当前 Agent 前端只为已登记模型开放真实候选参数。首个本机演练 scope 固定为 `agentDomainId=92001 / shisanshui / practice`；它是测试夹具，不从 URL 接受任意域 ID。只有十三张 `classic_v1` 规则包具备纯结算模拟器，因此工作区只允许调整其计分开关、水值和倍数；Slot、麻将、捕鱼、3快等页面显示“模型未登记”，不得借用十三张模型或展示伪造 RTP。

共享协议位于 `@gameing/contracts/agent-game-config`：`AgentGameConfigTargetDto`、`AgentGameConfigScopeDto`、`AgentShisanshuiScoringDto`、`AgentGameConfigWorkspaceDto`、`AgentGameConfigSimulationRequestDto/ResponseDto` 与 `AgentGameConfigPublishRequestDto/ResponseDto`，同时登记 read/simulate/publish API endpoint schema。HTTP 请求只提交游戏/难度 target，不提交 `agent_domain_id`；服务端从 JWT 当前 user、有效代理域和所需 capability 推导 scope。Browser application 使用相同解析端口，但只把固定 LOCAL_DEMO 身份/权限夹具解析为测试 scope。application 在进入仓储/模拟器前做 TypeBox 校验；模拟报告沿用 `GameMathSimulationReportDto`。报告需把 RTP 明确显示为“不适用”，因为这是多人水分结算模型；展示固定策略胜率、净分为零率、相公/打枪/全垒打率、净水分布、均值、方差和置信区间。修改候选后，先前报告不再符合候选，发布按钮必须失效，要求重跑模拟。发布事务不能信任客户端提交的模拟结果：服务端须按同一模型版本、候选配置、runs 和 seed 重算/核验报告后才能提交配置及审计，报告不需为此新增持久化表。

Browser adapter 使用唯一 `agent_game_config_workspaces` IndexedDB object store 保留每个 scope 的当前有效配置；模拟局与报告不落库。发布命令在同一个 IndexedDB 事务中更新当前配置，并向既有 `agent_audit_events` 追加 `CONFIG_PUBLISH` 快照，快照包含配置前后所有登记 key、原因、requestKey、模型版本、样本数及报告摘要。同一 requestKey 和完全相同命令重放返回原发布快照；key 用于不同配置/报告/目的时拒绝，即使之后已有更新发布也不把新状态误返回成旧命令结果。页面原因确认、模拟和发布只验证开发演练闭环，`LOCAL_DEMO` 明示，不代表实际 capability、服务端事务或线上生效。候选仍只在组件内存，离开/刷新不作为草稿保存。后端接入后，以 API adapter 替换 IndexedDB adapter，维持 DTO 与 application 边界；服务端发布必须重新从有效 user/domain/capability 得到 scope 并校验候选/报告，不信任客户端传来的域 ID。

## 6. 广播与社交隔离

平台事件实例和公告增加可选 `agent_domain_id`。为空表示平台级事件；有值表示仅在该代理域的大厅/子厅/游戏中显示。Socket.IO room 由服务端 JWT 与域授权加入，例如 `agent-domain:<id>`；客户端不能自行 join。HTTP 首屏快照、重连补拉、搜索和导出使用相同 scope 条件。

代理域公告只能由 `AGENT_ANNOUNCEMENT_MANAGE` 用户创建，模板和链接仍走平台白名单。系统全局公告可下发所有域，但代理不能把域广播提升为全局。域内活动效果仍须受游戏配置硬约束和游戏 handler 校验，跑马灯文案不得宣称没有实际配置支持的 RTP/赔率提升。

社交内容使用当前域范围。获授 `AGENT_SOCIAL_READ_PRIVATE_MESSAGES` 的域代理可以读取本域好友关系、私聊会话与历史消息；获授 `AGENT_SOCIAL_MODERATE` 可管理本域话题与公开内容。二者不授予客服 IM 权限。代理查看私聊、完整下线业务明细和导出操作写入不可变 `agent_audit_event`，只记录资源 ID/类型、目的和时间，不复制消息正文、密码或认证秘密。域间好友申请、私聊、话题/帖子访问默认拒绝。平台公共社区使用显式公共 scope，与代理域内容隔开。用户直属上级 `reward_type=LOSS` 的既有社交 gate 仍禁止该用户本人访问社交；代理获授的只读管理能力独立校验，不改变用户自己的社交开关。被换绑用户关联的会话整段跟随迁移，旧域参与者失去读取和发送权限；旧域不保留可查副本。

## 7. 数据结构建议

不创建 `agent` 表。数据库只为域本身保存独立 scope 实体：

### `agent_domain`

每个代理域一行，主代理关联统一 `user`。核心字段：`id BIGINT UNSIGNED`、`user_id BIGINT UNSIGNED`（域所有者）、`status`（PENDING_REVIEW=1、ACTIVE=2、SUSPENDED=3、REVOKED=4、WITHDRAWN=5）、`capabilities JSON`（仅保存代码已登记 capability codes）、`approved_at`、`suspended_at`、`created_at/updated_at/deleted_at`。`U(user_id)` 保证一名代理至多拥有一个域。权限变化经审计，不以额外 Role/RolePermission/AgentPermission 多表表达。

### 域范围字段

- `game_config` 增加可空 `agent_domain_id`；空表示平台基准配置，非空表示域 override。唯一键包含域、game/tier/scope/config_key；领域 service 校验域不能改变平台级不可覆盖字段。
- 持久化的 `game_event_instance` 增加可空 `agent_domain_id`，公告投影据此限域。若公告存放活动实例 JSON，不另建公告 recipient/link 表。
- 社交 scope 放在顶层实体：话题、帖子、好友关系、私聊会话、屏蔽和举报保存可空 `agent_domain_id`；空表示平台公共 scope。回复通过所属帖子继承 scope，消息通过所属会话继承 scope，不重复保存同一 scope。创建时由服务端解析写入，查询时必须与当前有效 scope 精确匹配。私聊会话双方有效 scope 必须相同。换绑后由 outbox 分批迁移；每个受影响用户对应一个带唯一键的任务，迁移未全部完成前该用户社交读写均暂停。
- 新增 `agent_audit_event`，记录代理查看下线资产/支付/游戏明细、私聊、导出、发布配置/广播等行为；不能复用仅记录 Admin 操作的 `admin_audit_event`。
- `agent_audit_event` 记录代理查看下线资产/支付/游戏明细、查看私聊、导出、发布配置/广播等动作；不保存消息正文或认证秘密。

全部新增列/表遵守[数据库设计规范与 Sequelize](../05_data/数据库设计规范与Sequelize方案.md)：非零状态常量、三个 DATETIME、注释、snake_case、引用 ID 字段命名与 Sequelize migration。`agent_domain_id IS NULL` 只表示共享平台作用域，不能当作 0 ID 或数据库状态。

## 8. 后台页面

```text
代理后台（响应式 Vue 3 / Element Plus）
├── 总览：域内在线、下线数量、游戏/档位摘要、广播状态
├── 下线管理：树形关系、脱敏资料、允许字段内的汇总
├── 游戏运营：域配置 → 参数说明/边界 → 1000/10000 次计算 → 对比 → 发布
├── 域内广播：范围预览（大厅/子厅/游戏）、定时/过期、状态
├── 社区：域话题/帖子（具备 moderation capability 时显示）
└── 操作记录：本人域内变更与 Admin 授权状态
```

代理后台和平台 Admin 可以共享 UI 组件、schema、API 契约与登录壳，但必须使用不同 route namespace、导航 capability 和服务端 application service。代理页面不直连 Sequelize、Redis 或 MySQL，也不复用 Admin API 的宽权限查询用例。

## 9. 实施顺序与验收

1. 建立 agent_domain 生命周期、Admin capability 配置和服务端授权中间件。
2. 实现从固定四级 `referral_binding` 推导用户有效域、下线范围、缓存失效和换绑处理。
3. 接入只读下线总览；用跨域数据构造测试，验证 IDOR、分页、聚合、导出均无法越域。
4. 扩展游戏配置 schema/计算器到 domain scope；验证越界候选拒绝、模拟无资金副作用、已开局快照不变。
5. 为事件公告及社交实体加 scope，验证不同域 Socket、HTTP 补拉、搜索、好友/私聊均隔离。
6. 验证 Admin 全局公告/平台社区仅按平台策略跨域分发，代理无法发布全局内容。

所有域数据读取路径都必须有 server-side scope 测试；仅检查前端菜单或 JWT 中的 domain ID 不合格。Admin 关闭/撤销代理域后，旧 JWT、旧 Socket room、缓存和正在运行的后台页面均须在下一次敏感操作时被拒绝。

## 10. 已确认与待定边界

- 子代理域对父代理完全隔离；父代理只看代理层级和聚合统计，不看子域明细内容。直属管理范围的业务明细由 `AGENT_DOWNLINE_READ` 授权，认证秘密永不开放。
- RTP 通过全局边界和计算器验证后即时发布；仍保留完整审计和平台停用/回滚能力。
- Admin 可授予代理查看本域私聊的独立 capability；不包括客服 IM。
- 下线换绑时迁移所有社交内容；跨域私聊整段随换绑用户迁入新域，旧域其他参与者失去读取权和发送权。
- 平台公共社区/广播与所有代理域内容分开；平台可发布跨域公告，代理不能。
- 首版 Agent 可否发布域级游戏配置、广播、执行社区审核均由 Admin 分别勾选 capability；默认最小权限，不因“成为代理”自动获得。
